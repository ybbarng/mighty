# 07. 공정성과 보안 설계

카드 게임에서 "해킹"은 대부분 **남의 패 엿보기**, **섞기 조작**, **규칙 위반**, **결과 조작** 넷 중 하나다. 서버 없이 친구끼리 하는 구조를 지키면서 이 넷을 어디까지 막을 수 있는지 정리한다. 사내 데브세미나 발표 거리로도 쓸 생각이라 단계별로 시연할 수 있게 나눈다.

## 1. 위협 모델

| 공격 | 예 | 누가 할 수 있나 |
| --- | --- | --- |
| A. 엿보기 | 개발자 도구로 남의 손패·바닥 카드·덱 순서 읽기 | 상태를 가진 기기의 주인 |
| B. 섞기 조작 | 방장이 자기에게 마이티·조커가 오도록 덱 순서를 정함 | 덱을 섞는 기기 |
| C. 규칙 위반 | 따라 낼 무늬가 있는데 다른 카드 내기, 없는 카드 내기 | 행동을 보내는 누구나 |
| D. 결과 조작 | 점수·트릭 승자를 바꿔서 알림 | 판정을 하는 기기 |
| E. 도움 프로그램 | 나온 카드 자동 세기, 수 추천 | 누구나 (공개 정보만 씀) |
| F. 짜고 치기 | 음성 채팅으로 패 알려 주기 | 누구나 (게임 밖) |

E와 F는 어떤 구조로도 막을 수 없다. 오프라인 마이티와 같다. 아래는 A~D를 다룬다.

## 2. 원작은 어땠나

원작 Mighty Network는 방장이 섞은 **덱 전체를 모든 참가자에게 보내고**, 각 기기가 같은 진행을 따로 돌렸다([04](./04-original-game-flow.md) 12절, `MFSM_Event.cpp`). 방장뿐 아니라 **모든 참가자가 A를 할 수 있었다.** 방장은 B도 할 수 있었다.

## 3. 대국 방식별로 보장되는 것

| 방식 | A 엿보기 | B 섞기 조작 | C 규칙 위반 | D 결과 조작 |
| --- | --- | --- | --- | --- |
| 원작 (덱 전체 전송) | 모두 가능 | 방장 가능 | 각자 엔진이 막음 | 각자 계산 |
| 지금: 혼자 + 컴퓨터 (브라우저 안) | 나만 가능 (손해 보는 사람 없음) | 해당 없음 | 엔진이 막음 | 해당 없음 |
| 방장 기기가 엔진 (1단계) | **방장만** 가능 | 방장 가능 | 방장 엔진이 막음 | 방장 가능 |
| + 공정한 섞기 + 판 끝 검증 (2단계) | 방장만 가능 | **막음** | 막음 | **잡아냄** |
| + 멘탈 포커 (3단계) | **아무도 못 함** | 막음 | 판 끝에 잡아냄 | 잡아냄 |
| 서버리스 방 (Durable Objects 등) | 서버 운영자만 | 운영자 | 막음 | 운영자 |

"막음"은 애초에 할 수 없다는 뜻, "잡아냄"은 해도 판이 끝나면 들킨다는 뜻이다.

## 4. 이미 들어 있는 바탕

| 장치 | 위치 | 하는 일 |
| --- | --- | --- |
| 보이는 정보만 만들기 | `viewOf` (`packages/engine/src/view.ts`) | 남의 패, 바닥 카드, 버린 카드(주공 외), 공개 전 프렌드, 난수 상태를 빼고 그 자리에서 보이는 것만 만든다. 무작위 대국 테스트가 매 단계 남의 패가 섞이지 않았는지 확인한다 |
| 행동 검사 | `step` + `decisionFor` | 할 수 없는 행동은 거절한다. 화면이 아니라 엔진이 판단한다 |
| 결정적 진행 | 상태 안의 난수(`rng.ts`) | 같은 시드·같은 행동이면 같은 결과 |
| 다시 돌리기 | `replay` (`replay.ts`) | 시작 조건 + 행동 기록 → 최종 상태. 시드나 기록을 바꾸면 어긋나는 것을 테스트로 확인한다 |
| 정해진 패로 시작 | `presetDeal` | 멘탈 포커처럼 덱을 엔진 밖에서 정할 때 검증용으로 쓴다 |

## 5. 2단계: 공정한 섞기와 판 끝 검증

### 공정한 섞기 (commit-reveal)

1. 각자 난수 `r_i`를 만들고 해시 `h_i = SHA-256(r_i)`만 보낸다(참가자는 방에 들어올 때).
2. 시작할 때 방장이 자기 것까지 **모든 해시를 먼저 알린다.** 참가자는 이것을 받은 뒤에야 `r_i`를 **방장에게만** 보낸다.
3. 시드 = `SHA-256(r_0 ‖ r_1 ‖ … ‖ r_n)`. 방장은 자기 해시를 먼저 알렸기 때문에 참가자 값을 본 뒤 자기 값을 바꿀 수 없다.
4. 게임이 끝나면 방장이 모든 `r_i`를 공개하고, 참가자가 해시와 맞는지, 자기 값이 그대로인지 확인한다.

처음 설계는 2단계에서 `r_i`를 모두에게 공개하는 것이었는데, 그러면 **참가자 누구나 시드를 계산해 덱 전체를 알 수 있다.** 그래서 공개는 게임이 끝난 뒤로 미뤘다. 방장은 시드를 알게 되므로 여전히 A(엿보기)는 할 수 있다. 막는 것은 B다.

구현: `apps/web/src/net/fairness.ts`, `host-room.ts`, `guest-room.ts`. 시험: `room.test.ts`(방장이 값을 바꿔치기하면 잡아내는지 포함).

### 판 끝 검증

게임이 끝나면 방장이 비밀 값들과 행동 기록을 모두에게 보낸다. 각 기기는 그 값으로 시드를 다시 만들고 기록으로 `replay`를 돌려 다음을 확인한다.

- 기록이 끝까지 거절 없이 돌아가는가 (C: 방장이 위반을 눈감아 주지 않았나)
- 내 화면에서 본 진행(받은 카드, 바닥, 승자, 점수)과 재생 결과가 같은가 (D)

어긋나면 그 판을 무효로 하고 기록을 남긴다.

### 받은 화면 전부 대조 (2026-10-21)

처음에는 판 끝 검증이 **마지막 화면만** 비교했다. 그러면 방장이 게임 중간에 다른 화면(예: 남의 점수, 낸 카드)을 보여 줬다가 마지막에만 맞춰도 들키지 않는다. 지금은 참가자가 받은 화면을 모두 적어 두었다가(`RemoteMatch.seen`), 기록을 한 걸음씩 다시 돌린 화면 목록에 **같은 차례로 모두 들어 있는지** 확인한다. 시험: `room.test.ts` "방장이 게임 중 보낸 화면 하나라도 조작하면 판 끝에 잡아낸다".

### 방장 확인: 서명 (2026-10-21)

링크를 아는 사람은 누구나 방에 들어와 있으므로, 처음에는 **먼저 "어서 와"라고 답한 연결**을 방장으로 믿었다. 그러면 다른 참가자가 새로 들어오는 사람에게 방장 행세를 할 수 있다.

1. 방장은 방을 열 때 ECDSA P-256 열쇠 쌍을 만든다(Web Crypto, `apps/web/src/net/identity.ts`).
2. 공개 열쇠의 지문(SHA-256 앞 16바이트, base64url 22글자)을 초대 링크에 넣는다: `?room=…&k=…`.
3. 참가자는 입장 요청에 임의의 값(nonce)을 넣는다. 방장은 `게임 | nonce | 참가자 연결 아이디 | 자리 | 토큰`에 서명해 공개 열쇠와 함께 보낸다.
4. 참가자는 공개 열쇠의 지문이 링크와 같은지, 서명이 맞는지, 서명된 연결 아이디가 **자기 것인지** 확인한다. 통과한 연결만 방장으로 정하고, 그 뒤로는 그 연결의 메시지만 방장 메시지로 받는다(대기실, 시작, 화면, 판 끝 공개, 채팅, 내보내기, 자리 없음).

3의 연결 아이디 덕분에 중간자(가짜 방장이 참가자의 요청을 진짜 방장에게 그대로 넘기는 것)도 걸린다. 진짜 방장은 중간자의 연결 아이디에 서명하기 때문이다. 시험: `room.test.ts` "방장 확인(서명)".

### 검증 알림의 보낸 자리

참가자는 판 끝 검증 결과를 모두에게 직접 알린다. 예전에는 알림 안의 자리 번호를 그대로 믿어서, 참가자가 남의 자리로 "실패"를 알릴 수 있었다. 지금은 대기실 정보에 자리마다 연결 아이디(`LobbySeat.peerId`)를 넣고, 알림을 보낸 연결이 그 자리의 연결과 다르면 무시한다. 방장이 대기실 정보를 거짓으로 보내면 이 확인도 속을 수 있다(방장을 믿지 않는 장치가 아니라 참가자끼리의 사칭을 막는 장치다).

### 남은 한계

- 방장은 모든 패를 볼 수 있다(멘탈 포커 전).
- 채팅은 모두 방장을 거친다. 방장은 남의 이름으로 말을 지어낼 수 있다. 참가자끼리는 서로를 사칭할 수 없다.
- 판 끝 검증은 게임이 끝날 때 한 번이다. 판마다 약속·공개를 새로 하면 더 일찍 잡는다.
- 모의 침투(2026-10-21)로 찾은 공격과 처리: [12-redteam-2026-10-21.md](./12-redteam-2026-10-21.md). 행동 바꿔치기, 컴퓨터 조종, 시드에서 참가자 값 빼기, 기록 숨기기, 토큰 가로채기 등은 지금 잡거나 막는다.

## 6. 3단계: 멘탈 포커

방장도 남의 패를 볼 수 없게 한다. 교환 가능한 암호(SRA, Pohlig–Hellman)를 쓴다. `E_a(E_b(x)) = E_b(E_a(x))`라서 잠근 순서와 상관없이 풀 수 있다.

### 기본 절차

1. **공통 준비**: 큰 소수 `p`를 정하고, 카드 53장을 `p`의 이차잉여인 수로 대응시킨다(이차잉여 여부로 정보가 새지 않게).
2. **섞기**: 각자 차례로 덱 전체를 자기 열쇠로 잠그고 섞어 다음 사람에게 넘긴다. 끝나면 모두가 섞었고 모두가 잠근 덱이 된다.
3. **카드마다 따로 잠그기**: 각자 자기 전체 열쇠를 풀고 카드 자리마다 다른 열쇠로 다시 잠근다. 그래야 한 장의 열쇠를 공개해도 다른 카드가 드러나지 않는다.
4. **나눠 주기**: 자리 k의 카드를 j에게 줄 때, j를 뺀 모두가 자리 k의 열쇠를 공개한다. j만 자기 열쇠로 마지막 잠금을 풀어 카드를 본다.
5. **카드 내기**: 낸 사람이 그 자리 열쇠를 공개하면 모두가 카드를 본다. 손에 있던 자리가 아니면 바로 거절된다.

### 마이티에 맞추기

| 장면 | 처리 |
| --- | --- |
| 바닥 카드 | 당선 뒤 남은 자리들을 주공에게 4번 절차로 준다 |
| 버린 카드 | 주공이 잠근 채로 둔다. 점수 계산에 버린 점수 카드 수가 필요하므로 판 끝에 공개한다 |
| 딜미스 | 선언한 사람이 자기 패 열쇠를 공개한다(원작도 패를 보여 줬다) |
| 6·7마 죽이기 | 지목한 카드를 가진 사람이 스스로 밝힌다. 거짓말은 판 끝 검증에서 잡힌다. 다시 섞기는 2~3번 절차를 남은 카드로 한 번 더 한다 |
| 카드 프렌드 | 그 카드를 낼 때 자연히 드러난다 |
| 초구 프렌드 | 첫 트릭 승자. 공개 정보만으로 정해진다 |
| 무늬 따라내기 | 손패를 보지 않고는 확인할 수 없다. 판 끝에 모든 열쇠를 공개하고 `replay`로 위반을 잡아낸다 |

### 엔진에 필요한 변화

지금 `step`은 전체 상태(모든 손패)를 가진 쪽이 돌린다. 멘탈 포커에서는 아무도 전체 상태를 갖지 않으므로

- 진행 중에는 공개 정보만으로 다음 상태를 계산하는 "공개 진행"과, 자기 패로만 확인하는 "내 행동 검사"로 나눈다. 트릭 승자, 프렌드 공개, 점수는 공개 정보만으로 계산된다
- 판 끝에는 공개된 열쇠로 덱을 복원해 `presetDeal`로 `replay`를 돌려 전체를 검증한다. 6·7마 다시 섞기를 위해 `replay`가 "엔진 밖에서 정한 다시 섞기 결과"를 받을 수 있어야 한다

계산량: 5명 × 53장 × 몇 번의 모듈러 거듭제곱. 브라우저 `BigInt`로 충분하고, 2048비트라도 한 판에 1초 안쪽으로 예상한다(구현 때 측정).

## 8. 발표 시연 아이디어

1. **원작 방식**: 덱 전체를 받는 클라이언트를 흉내 내고, 개발자 도구로 모두의 패를 꺼내 보인다.
2. **방장 방식**: 방장 아닌 사람의 개발자 도구에는 자기 패만 있다. 방장은 다 보인다.
3. **섞기 조작 시도**: 방장이 시드를 바꿔 끼우면 commit-reveal 확인에서 바로 들킨다.
4. **결과 조작 시도**: 방장이 승자를 바꿔 알리면 판 끝 `replay`에서 어긋난다.
5. **멘탈 포커**: 방장의 개발자 도구에도 남의 카드는 큰 숫자(암호문)로만 보인다.
6. **규칙 위반 시도**: 고친 클라이언트로 무늬를 안 따라 내면, 진행은 되지만 판 끝 검증에서 잡힌다.
