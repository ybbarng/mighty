# 38. 시험을 빠르고 결정적으로 만들며 얻은 것 (2026-10-29~30)

사용자 요구: "테스트는 빨라야 해", "전체 테스트가 최대한 빠르고, 효율적이고, flaky하지 않기를". 이틀 동안 단위 시험과 화면 시험을 손본 결과와 교훈이다. 지킬 규칙은 CLAUDE.md "작업 규칙"과 docs/21 10절에도 있다.

| | 전 | 후 |
|---|---|---|
| 단위 시험 전체(이 기계) | 194초(부하로 멈춘 시험 포함) | 약 16초, 2400개 |
| 화면 시험 전체(`FAIR_MULTI=1`, 이 기계) | 450초 | 약 140초 |
| 화면 시험 시간 합 | 2,531초 | 787초 |

## 1. flaky 시험은 대개 진짜 버그였다

가끔 실패하는 시험을 쫓아가 보니 대부분 공통 온라인 방의 실제 경합이었다. 모두 친구와 대전할 때 생길 수 있다.

| 증상 | 원인 | 고친 곳 |
|---|---|---|
| 새로고침한 참가자가 "방장이 시드를 공개하지 않았다" | 내 패를 다 알기 전 판이 끝나 검증 재료가 없음 | `guest-room.ts` |
| "방장이 더미 카드를 엔진과 다르게 열었다" | 다시 받은 카드 열기 요청을 처리하기 전에 기록 검증 | `hwatu-table.ts` |
| "기록 속 내 행동이 내가 보낸 것과 다르다" | 거절된 행동이 저장 목록에 남음, 남의 차례 화면을 내 행동 결과로 착각 | `guest-room.ts`, `host-room.ts`(`mine`) |
| 참가자가 끝없이 기다림 | 다시 세우는 중인 방장이 받은 행동을 소리 없이 버림 | `host-room.ts` |
| 끊긴 사람 투표가 열리지 않음 | 입장 확인(비동기) 중 나간 연결을 자리에 앉힘 | `host-room.ts` |
| 방장 새로고침 뒤 판 끝 검증이 오지 않음 | 방장 서명 확인 전에 온 메시지를 "방장 아님"으로 버림 | `guest-room.ts` |

→ 시간 상한을 늘렸다면 이 버그들은 남았다. flaky는 단서다.

## 2. "느린 것"과 "멈춘 것"을 먼저 가린다

겉보기는 둘 다 시간 초과다. 단계마다 시각을 남기면 갈린다. 느리면 시험의 일을 줄이고, 멈추면 경합을 찾는다(처방이 정반대).

## 3. 부하 아래에서만 드러난다

- 따로 240번 통과한 시험이 전체 시험과 함께 돌자 멈췄다. 고친 뒤에는 **전체 시험 두 벌을 동시에** 돌리며 반복한다.
- 원인을 찾으면 **부하 없이도 반드시 재현하는 시험**(`MemoryNetwork`·`ManualClock`으로 순서를 강제)을 먼저 만들고 고친다.

## 4. 시험은 역할만큼만 일한다

| 하던 것 | 바꾼 것 | 그래도 보장하는 것 |
|---|---|---|
| 섞기 증명 53장 | 4장(두 군) | 증명 정합·변조 잡기는 덱 크기와 무관 |
| 마이티 변형 한 판 끝까지(세 크기) | 첫 트릭까지 | 인원별 장면은 모두 첫 트릭 전 |
| 무작위 시드 15개 | 4개 | 180판을 수마다 확인 |
| 단위 시험 안 세기 비교 | bench로 | 세기는 따로 잰다 |
| 판 끝 화면을 보려고 한 판 끝까지 | 기권 등 가장 짧은 길 | 같은 판 끝 화면 |
| 여러 탭 멘탈 포커 두 판 | 한 판 | 판 잇기는 방 단위 시험이 본다 |

"무엇을 보장하려는가"를 먼저 적으면 어디서 멈춰도 되는지 보인다. 확인 범위(판 끝·게임 끝 검증, 부정 감지)는 줄이지 않는다.

## 5. 운을 없애면 시간도 일정해진다

마이티 방장 새로고침 시험이 0.9~185초로 들쭉날쭉했다(모두 공약 포기 → 다시 나누기). 방장이 늘 높게 공약하게 하자(`hostBidsTop`) 1.3초로 일정해졌다. 운에 따라 다시 시도하기보다 운이 들어갈 자리를 없앤다. 멘탈 포커는 각 기기의 난수로 패가 정해져 방장 시드로 고정할 수 없다는 점도 알아 둔다.

## 6. 기다림은 시간이 아니라 신호로

- 화면이 준비를 알린다: `data-hydrated`(저장값 읽기 끝), `data-moving`, `data-dealing`. 준비 전에 누르면 누름이 사라지거나 늦게 읽힌 저장값이 설정을 덮었다.
- `expect.poll` 기본 간격은 1초까지 늘어난다. 컴퓨터 차례마다 늦게 알아채 나이롱뽕 온라인 57초 → 간격 50ms 고정 후 10초.
- 연출·컴퓨터 대기·제한 시간은 시험에서 줄이거나 옮길 수 있게 둔다: 움직임 줄이기(화면 시험 기본), 시험 속도(`useTestSpeed`, 제품의 `paced`), `Clock`.

## 7. 줄이기 전에 잰다

효과는 몇 군데에 몰렸다(마이티 변형 748초가 전체의 30%). 시험별 시간 표부터 만든다. 작은 것도 쌓인다: 화면이 필요 없는 시험은 jsdom 대신 node 환경.

## 8. 공통 코드는 고치는 효과도, 깨지는 범위도 넓다

공통 온라인 방을 고치면 다섯 게임이 함께 고쳐진다. 대신 공통 코드를 바꾸면 전체 화면 시험을 돌린 뒤 올린다.

## 9. 올리는 것을 그대로 확인한다

여러 작업이 한 작업 공간에서 돌면 push 전 검사가 남의 고치던 파일까지 돈다. 그럴 때는 올릴 커밋만 깨끗한 worktree에 꺼내 확인한다.

## 남은 것

- 고스톱 온라인 방이 부하 아래 20번에 1번 멈춤(조사 중).
- 윷놀이 "무르기 뒤 새 말 내기" 화면 시험 1회 실패, 재현 못 함.
