# 05. 화면 배치 (원작 분석과 웹 배치안)

원작 Mighty Network 4.0의 화면 배치를 소스에서 읽고, 왜 그렇게 놓았는지와 지금 화면에서도 효율적인지 따져 본 뒤, 웹 리메이크의 가로·세로 배치안과 좌표 계산 규칙을 정한다. [03-plan.md](./03-plan.md)의 "화면 방향" 절(둘러앉은 원 테이블, 이벤트로 재생하는 애니메이션, 낼 수 있는 카드만 밝게, 세로 폰 지원)을 이어받는다.

- 원작에는 LICENSE가 없다. 코드는 옮기지 않고 동작과 수치만 사실로 적는다.
- 근거는 `파일:행`으로 적는다. 행 번호는 UTF-8 변환본 기준이다.
- 원작 수치를 직접 계산한 값에는 "계산"이라고 붙인다. 소스만으로 확신할 수 없는 부분은 **추정**이라고 적는다.
- 와이어프레임은 글자 폭이 어긋나지 않게 ASCII만 쓴다. 기호 뜻은 각 그림 아래에 적는다.

---

## 0. 결론 먼저

1. 원작은 **정사각형에 가까운 창(기본 약 490×445 화면 영역)** 을 기준으로 만든 배치다. 다른 사람 손패를 뒷면으로 펼쳐 그리는 데 화면의 약 35%를 쓰지만, 그 그림이 주는 정보는 "몇 장 남았나"뿐이다. 이 부분이 가장 비효율적이다.
2. 원작에서 그대로 가져올 만한 것: **바닥에 낸 카드를 낸 사람 쪽으로 치우쳐 놓기**, **딴 점수 카드를 그 사람 자리 옆에 쌓아 보이기**(야당 쪽만), **공약 상자를 내 손패 바로 위에 띄우기**, **조커 무늬 선택을 누른 자리 옆에 띄우기**, **낼 수 있는 카드만 마우스에 반응하기**, **진행 중엔 창 밖 대화상자를 쓰지 않고 판 위 상자로 처리하기**.
3. 새 배치는 **다른 사람은 작은 "자리 판"(이름·장수·딴 점수 카드·상태)** 으로 줄이고, 아낀 면적을 **내 손패와 바닥**에 준다.
4. 공약·바닥 카드 교환·프렌드 지정을 하는 동안 바닥은 비어 있다. 그래서 **행동 패널은 바닥 자리(판 가운데)에 띄운다.** 내 손패와 다른 사람 자리는 가리지 않는다.
5. 자리는 **판 영역에 맞춘 타원 위의 각도 표**로 정한다. 같은 표가 가로(넓은 타원)와 세로(높은 타원)에 모두 맞는다.
6. 구현은 **바깥 틀은 CSS grid, 카드와 자리 판은 화면 전체를 덮는 한 장의 절대 좌표 층**으로 나눈다. 카드가 손패에서 바닥으로, 바닥에서 점수 더미로 옮겨 가려면 좌표계가 하나여야 하기 때문이다.

## 1. 원작 분석

### 1.1 해상도 가정

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 카드 그림 크기 | 71×96 (Windows 기본 카드와 같은 크기) | `res/Sa.bmp`, `res/Back1.bmp` 파일 정보 |
| 무늬 아이콘 | 20×20 | `res/Spade.bmp` |
| 기본 창 위치·크기 | (100, 30) ~ (600, 550), 즉 500×520 | `Option.cpp:106-109` |
| 창 안 그림 영역 | 메뉴·제목줄·상태 막대를 빼면 약 490×445 (계산, Windows 98 기본 테두리 기준 **추정**) | `MainFrm.cpp:62-90` |
| 최대화 | 작업 영역 **높이에 맞춘 정사각형**으로만 커진다 | `MainFrm.cpp:161-174` |
| 기본 글꼴 | 돋움 굵게, 작은 글꼴 14px(카드 확대 비율만큼 커진다), 중간 1.5배, 큰 2.5배 | `Board_Layout.cpp:221-270` |

창 위치 30 + 높이 520 = 550이라 640×480 화면에는 세로로 들어가지 않는다. **800×600 화면에서 창으로 띄우는 것**을 기준으로 잡은 것으로 본다(추정). 최대화를 정사각형으로 묶은 것은 배치 공식이 정사각형에 가까운 화면에서만 보기 좋기 때문이다.

### 1.2 화면을 나누는 네 가지 영역

판 그림은 모두 `CalcRect` 한 함수가 계산한다(`Board_Layout.cpp:272-528`). 영역은 네 가지다(`Board.h:152-161`).

| 영역 | 뜻 | 위치 |
| --- | --- | --- |
| `CR_CENTER` | 바닥(트릭) | 화면 정가운데, 폭 `3W - W/5`, 높이 `2H + 8` (W·H는 카드 폭·높이) (`Board_Layout.cpp:325-333`) |
| `CR_SCORE` | 딴 점수 카드 | 각 자리의 손패 바로 안쪽에 반쯤 겹쳐서 (`:373-411`) |
| `CR_HAND` | 손패 | 각 자리 화면 가장자리 (`:412-467`) |
| `CR_HIDDEN` | "가져가는 곳" | 그 자리 쪽 **화면 바깥**(가장자리에서 5px 밖) (`:507-525`) |

기본 크기(71×96)로 계산하면 바닥 영역은 199×200이다(계산).

### 1.3 인원별 자리 위치

자리는 "내 자리(아래)부터 시계 방향으로 0번, 1번, …"으로 매기고, 인원마다 각 자리에 가로 위치 5단계(왼쪽 끝·왼쪽 가운데·가운데·오른쪽 가운데·오른쪽 끝)와 세로 위치 5단계(위·위쪽 가운데·가운데·아래쪽 가운데·아래)를 하나씩 붙인 표를 쓴다(`Board_Layout.cpp:300-315`). 시계/반시계 방향은 옵션이고 기본은 시계 방향이다(`Board_Layout.cpp:317-319`, `Option.cpp:30`).

| 인원 | 0(나) | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 2 | 아래 가운데 | 위 가운데 | | | | | |
| 3 | 아래 가운데 | 왼쪽 끝·위쪽 가운데 | 오른쪽 끝·위쪽 가운데 | | | | |
| 4 | 아래 가운데 | 왼쪽 끝·가운데 | 위 가운데 | 오른쪽 끝·가운데 | | | |
| 5 | 아래 가운데 | 왼쪽 끝·아래쪽 가운데 | 위·왼쪽 가운데 | 위·오른쪽 가운데 | 오른쪽 끝·아래쪽 가운데 | | |
| 6 | **아래·오른쪽 가운데** | 아래·왼쪽 가운데 | 왼쪽 끝·가운데 | 위·왼쪽 가운데 | 위·오른쪽 가운데 | 오른쪽 끝·가운데 | |
| 7 | 아래 가운데 | 왼쪽 끝·아래 | 왼쪽 끝·위쪽 가운데 | 위·왼쪽 가운데 | 위·오른쪽 가운데 | 오른쪽 끝·위쪽 가운데 | 오른쪽 끝·아래 |

- 왼쪽 끝·오른쪽 끝 자리는 **세로로 긴 영역**이고 카드를 90도 돌려 그린다(`Board_Layout.cpp:364`, `BmpMan.cpp:132`).
- 카드를 펼치는 방향은 왼쪽 자리는 아래→위, 오른쪽 자리는 위→아래, 아래 자리는 왼쪽→오른쪽, 위 자리는 오른쪽→왼쪽이다(`Board_Layout.cpp:367-371`). 즉 **모두 시계 방향으로 펼친다.** 판을 둘러앉아 각자 자기 앞에 패를 펼친 모습을 흉내 낸 것이다.
- 6인만 내 자리가 가운데가 아니다. 아래에 두 자리를 두어 정육각형 모양을 맞췄다.
- 7인은 양옆 사람이 두 명씩이라 그 손패 영역을 카드 폭만큼 줄인다(`Board_Layout.cpp:415-419`). 5·6·7인의 위쪽 사람도 카드 폭의 1/4만큼 줄인다(`:440-447`).

### 1.4 내 손패

- 아래 가운데에 가로로 펼친다. 영역 폭은 기본 `3.5W`이고, 화면이 넓으면 남는 폭의 절반을 더 쓴다(`Board_Layout.cpp:449-452`).
- 카드가 영역에 다 들어가면 겹치지 않고 가운데로 모으고, 넘치면 **영역 폭 안에 같은 간격으로 겹친다**(`Board_Layout.cpp:488-505`). 간격은 `(영역 폭 - W) / (장수 - 1)`이다.
- 기본 창(490×445)에서 영역 폭은 약 255px이다. 10장이면 한 장이 약 20px씩 보이고(카드 폭의 29%), 바닥 카드를 받은 13장이면 약 15px씩 보인다(카드 폭의 22%)(계산).
- 마우스를 올리면 카드 높이의 1/20만큼 올라가고, 바닥 카드에서 버릴 카드로 고르면 1/5만큼 올라간다(`Board.h:182-185`, `Board_Draw.cpp:69-79`).
- 손패는 기루다를 왼쪽에 둘지, A를 왼쪽에 둘지 옵션에 따라 정렬한다(`MFSM_Server.cpp:74-75`, `:111-115`).

### 1.5 다른 사람 손패

- 다른 사람 손패도 **실제 장수만큼 뒷면 카드를 펼쳐 그린다**(`Board_Draw.cpp:316-344`, 앞면을 숨기는 곳은 `:59-60`). 사람이 아닌 관전 상태이거나 딜미스를 보여줄 때만 앞면이 보인다(`:320-321`).
- 장수만 따로 숫자로 보여주지는 않는다. 자리 위에 마우스를 올리면 "이름 N 장 득점" 도움말만 뜬다(`Board_UI.cpp:241-261`, `:304-307`).

### 1.6 바닥(트릭)

- 바닥 영역(199×200) 안에서 **각 사람이 낸 카드를 그 사람 쪽으로 치우쳐 놓는다.** 자리 표의 가로·세로 위치를 그대로 써서, 왼쪽 사람 카드는 바닥 영역 왼쪽 끝, 위 사람 카드는 위쪽 끝, 내 카드는 아래쪽 끝에 붙인다(`Board_Layout.cpp:335-356`).
- 선부터 낸 순서대로 그려서 나중 카드가 위에 온다(`Board_Draw.cpp:89-130`).
- 트릭 진행 중이 아니면 바닥 자리에 **남은 덱(바닥 카드 포함)을 쌓인 모양으로** 그린다(`Board_Draw.cpp:304-312`, 쌓인 높이 계산 `:203-211`).

### 1.7 딴 점수 카드

- 점수 영역은 손패 영역보다 판 가운데 쪽으로 반 장 들어간 자리에 있고, **손패보다 먼저 그려서 손패 뒤로 반쯤 삐져나온 모양**이 된다(`Board_Draw.cpp:266-285`가 먼저, 손패는 `:316-344`). 위·아래 자리는 카드 높이의 1/2, 옆 자리는 카드 폭의 1/2만큼 보인다(`Board_Layout.cpp:398-409`, `:379-386`, 계산).
- 점수 영역 폭은 가로 자리에서 `1.75W`라서(`Board_Layout.cpp:393-396`) 8장쯤 쌓이면 한 장이 7~8px만 보인다(계산). 카드 하나하나를 읽기보다 **"얼마나 쌓였나"를 보는 용도**다.
- 이 더미에 오는 카드는 **트릭을 이긴 사람이 주공도, 공개된 프렌드도 아닐 때의 점수 카드뿐**이다. 그 밖의 카드(점수 카드가 아니거나 여당이 딴 카드)는 이긴 사람 쪽 **화면 밖**(`CR_HIDDEN`)으로 날아가 사라진다(`PlayerHuman.cpp:738-773`). 숨은 프렌드가 공개되면 그 사람 더미는 비운다(`MFSM_Server.cpp:376-383`, [04](./04-original-game-flow.md) 7.4절).
- 규칙 옵션 `bHideScore`를 켜면 점수 더미도 뒷면으로 그린다(`Board_Draw.cpp:270`).

### 1.9 화면 크기 변화 대응

창 크기가 바뀔 때마다 카드 크기와 글꼴을 다시 계산하고 전체를 다시 그린다(`Board.cpp:285-321`).

**카드 확대 비율** (`Board_Layout.cpp:173-219`, 카드 확대 옵션 기본 켬 `Option.cpp:59`):

- 원래 크기가 알맞은 화면은 폭 `2.5W + 2H` ~ `3.5W + 2H`, 높이 `4.5H` ~ `5.5H`다. 71×96이면 폭 370~440, 높이 432~528이다(계산).
- 한쪽이라도 작으면 두 방향 중 더 작은 비율로 줄인다.
- 두 방향 모두 크면 더 작은 비율로 키우되 **0.5배 단위로 반올림**한다. 그래서 1.25배가 필요한 화면에서 1.5배가 되기도 한다.

**두 가지 배치 구간** (`Board_Layout.cpp:375-465`):

- 폭이 `4W + 2H`(기본 476)보다 좁으면 옆 사람 손패를 화면 끝이 아니라 **가운데 쪽으로 당겨** 놓는다.
- 높이가 `5.5H`(기본 528)보다 낮으면 위·아래 손패를 화면 끝이 아니라 **가운데에서 1.75H 떨어진 곳**에 놓는다. 그래서 높이가 5.5H보다 낮으면 위 사람 손패의 윗부분과 내 손패의 아랫부분이 화면 밖으로 잘린다. 기본 창(높이 약 445)에서는 위·아래로 약 40px씩, 즉 카드 높이의 40% 정도가 잘린다(계산). 줄이는 기준이 4.5H이므로 **카드 반 장까지 잘리는 것을 허용한 설계**다(추정). 숫자가 적힌 카드 위쪽 모서리는 그래도 보인다.

**애니메이션 중에는 창 크기 변경을 막는다.** 카드가 날아가는 동안과 섞는 동안 창 크기를 잠그고, 끝난 뒤에 바뀐 크기를 한 번에 반영한다(`Board_Draw.cpp:577-578`, `:657-659`, `MainFrm.cpp:176-221`).

### 1.10 DSB(음영 상자)

DSB는 대화상자를 창으로 띄우지 않고 **판 그림 위에 직접 그리는 반투명 상자**다(`DSB.h:15-19`). 옵션 창 설명도 "음영 상자는 Windows의 대화 상자와 같은 것입니다"라고 적혀 있다(`Mighty.rc:363-380`).

- 위치는 판 정가운데 기준 오프셋(글꼴 높이 단위)이나 화면 좌표로 정한다(`DSB.cpp:375-390`, `DSB.h:43-58`). 화면이 커지면 단위도 같이 커진다. `SetFixed`를 부른 상자는 크기가 고정된다.
- 상자 종류는 세 층이다: 맨 아래(`Below`), 보통, 모달(`Modal`). 모달 상자가 있으면 그 상자 말고는 클릭을 받지 않는다(`Board_DSB.cpp:55-88`, `Board_UI.cpp:22-69`).

### 1.11 InfoBar(상태 막대)

창 맨 아래 상태 막대를 네 칸으로 나눠 쓴다(`InfoBar.cpp:102-126`).

2. 공약 숫자
3. 프렌드 글자("♥A 프랜드", "초구 프랜드", "노 프랜드", "-미정-"). 섞는 동안에는 이 칸이 진행 막대로 바뀐다(`InfoBar.cpp:300-348`, `Board_Draw.cpp:703-705`).
4. 진행 글자("○○ 님 차례입니다", "○○ 님이 이번 턴을 이겼습니다" 등). 채팅할 때는 이 칸이 입력창으로 바뀐다(`InfoBar.cpp:210-239`).

### 1.12 대화상자와 메뉴

- 메뉴는 "게임"(점수판 보기, 옵션, 초기 메뉴로, 종료)과 "도움말" 둘뿐이다(`Mighty.rc:76-90`).
- 옵션·규칙은 탭이 여러 개인 **모달 창**(property sheet)이다(`DOption.h:13`, `DRule.h:13`). 판을 시작하기 전에 쓰는 화면이라 모달이어도 문제가 없다.
- 점수판("전적")은 **모달이 아닌 작은 도구 창**으로, 켜 두면 다음 실행에도 켜진다(`Mighty.rc:600-604`, `DScoreBoard.cpp:63-94`).
- 정리하면 **게임 진행에 필요한 선택은 모두 판 위 상자(DSB)로, 설정은 창 밖 모달로** 나눴다.

### 1.13 애니메이션과 속도 옵션

**카드 날리기** (`Board_Draw.cpp:551-672`, `Board_SE.cpp:262-378`):

- 시작 칸과 끝 칸 사이를 **직선으로 같은 속도**로 옮긴다(가속·감속 없음)(`Board_Draw.cpp:629-635`).
- 그림자 깊이를 바꿔 손에서 떠오르거나 판에 내려앉는 느낌을 낸다. 손패·가져가는 곳은 "높은 곳", 바닥·점수 더미·덱은 "낮은 곳"으로 친다(`Board_Draw.cpp:612-624`, `Board_SE.cpp:283-285`).
- 걸리는 시간은 `20 + (10 - 카드속도) × 100` ms이고 "빠름" 모드는 그 40%다(`Board_SE.cpp:326-327`). 카드속도 기본값 5이면 **보통 520ms, 빠름 208ms**다(계산, `Option.cpp:65`).
- 프레임 수는 "부드러움" 옵션으로 정하고 기본 30프레임이다(`Board_SE.cpp:330-332`, `Option.cpp:66`). 늦어지면 프레임을 건너뛰어 시간을 맞춘다(`Board_SE.cpp:359-372`).
- "카드를 부드럽게 이동시킴"을 끄면 2프레임으로 거의 순간 이동한다(`Board_SE.cpp:262-300`, `Mighty.rc:382-405`).

### 1.14 조작

- 내 차례에 **낼 수 있는 카드 위에서만** 커서가 손 모양이 되고 카드가 살짝 올라간다(`Board.cpp:361-369`, `:430-434`, `Board_UI.cpp:155-188`). 낼 수 없는 카드는 그대로다. **어둡게 칠하지는 않는다**(`Board_Draw.cpp:26-87`에 그런 처리가 없다).
- **한 번 클릭하면 바로 낸다.** 확인 단계가 없다(`Board_UI.cpp:72-96`, `PlayerHuman.cpp:674-690`). 카드가 아닌 곳을 누르면 삑 소리를 낸다(`Board_UI.cpp:90-93`).
- 조커·조커콜을 선으로 내면 커서 옆에 선택 상자가 뜨고 "취소"를 고르면 다시 카드를 고른다(`PlayerHuman.cpp:674-690`).
- 바닥 카드 교환은 손패 카드를 클릭해 토글하고 가운데 상자의 "확정"을 누른다(`DElection.cpp:496-545`).

### 2.3 지금 화면 비율에서

**16:9 가로(예: 1280×720)** 를 원작 공식에 넣으면(계산):

- 높이 기준으로 1.36배가 필요한데 0.5배 단위로 올려 **1.5배(106×144)** 가 된다. 높이 5.5H(792)가 720보다 커서 위·아래 손패가 36px씩 잘린다.
- 바닥은 약 297×296인데 옆 자리 손패는 화면 양 끝(0~144, 1136~1280)에 붙는다. 바닥과 옆 자리 사이에 **양쪽으로 약 350px씩 빈 띠**가 생긴다. 폭의 절반 가까이를 쓰지 않는다.
- 맞는 것: 내 손패 폭이 넉넉해져 10장이 60px 간격으로 편하게 보인다.

**9:19.5 세로 폰(예: 390×844)** 을 넣으면(계산):

- 폭 390이 `4W + 2H`(476)보다 좁아 옆 사람 손패를 가운데 쪽으로 당기는데, 그 위치가 x = -68 ~ 28이라 **손패 대부분이 화면 밖**이다. 위 두 사람 손패도 서로 겹치며 양쪽으로 잘린다.
- 높이는 남아서 위 손패(0~96), 바닥(322~522), 내 손패(748~844) 사이에 **세로 약 45%가 빈다.**
- 결론: 원작 공식은 세로 화면에서 쓸 수 없다. 공식을 고치기보다 배치 원리부터 다시 정해야 한다.

### 2.4 가져올 것과 버릴 것

가져온다:

- 내 자리는 항상 아래, 나머지는 시계 방향으로 둘러앉기
- 바닥 카드를 낸 사람 방향으로 치우치기, 낸 순서대로 위에 쌓기
- 야당(과 숨은 프렌드)의 점수 카드를 그 사람 자리에 쌓아 보이기, 프렌드 공개 때 비우기
- 진행 중 선택은 판 위에서(창 밖 모달 금지), 설정만 별도 화면
- 공약 선택은 내 손패 가까이, 특권·프렌드는 빈 바닥 자리에, 조커 무늬는 누른 카드 옆에
- 낼 수 있는 카드만 반응, 마우스 한 번 클릭으로 내기
- 시간이 지나면 사라지는 알림 상자(공약, 조커콜, 프렌드 공개)
- 속도 옵션(전체 배속, 섞기·나눠 주기 생략)

버린다:

- 남의 손패를 실제 장수만큼 펼치기 → 장수 숫자 + 작은 뒷면 묶음
- 90도 돌린 옆 자리 카드
- 기루다·공약을 아래 상태 막대에 두기 → 판 위 고정 표시(HUD)
- 이름 테두리만으로 차례 표시 → 자리 판 전체 강조
- 손패가 화면 밖으로 잘리는 배치(터치에서 불리)
- 직선·같은 속도 이동 → 감속 곡선
- 트릭 모으기를 한 장씩 차례로(인원 × 208ms) → 한 번에 모아 한 번에 이동
- 애니메이션 중 크기 변경 잠금 → 목표 좌표 다시 잡기

## 3. 제안

### 3.1 원칙

1. **면적은 정보 우선순위대로 나눈다.** 내 손패 > 바닥 > 현재 차례·공약·기루다 > 각자 딴 점수 카드 > 돈.
2. **다른 사람은 "자리 판" 하나로 줄인다.** 손패를 펼쳐 그리지 않는다.
3. **판 가운데는 시간에 따라 쓰임이 바뀐다.** 선거·특권·프렌드 지정 동안에는 행동 패널이, 트릭 동안에는 바닥 카드가 같은 자리를 쓴다. 둘이 동시에 필요한 때가 없다.
4. **내 손패와 바닥은 절대 가리지 않는다.** 패널은 판 가운데, 알림은 자리 판 옆, 점수판은 서랍.
5. **방향마다 다른 화면을 만들지 않는다.** 같은 규칙(영역 나누기 + 타원 위 자리 + 카드 크기 공식)에 화면 크기만 넣어 가로·세로를 모두 만든다.
6. **애니메이션은 진행을 막지 않는다.** 엔진 `events`를 큐에 넣고 화면이 따라 재생한다. 밀리면 배속을 올린다.

### 3.2 정보 우선순위와 시각 비중

| 순위 | 정보 | 표시 | 목표 비중(가로 16:9) | 목표 비중(세로 폰) |
| --- | --- | --- | --- | --- |
| 1 | 내 손패 | 큰 카드, 낼 수 있는 카드만 밝게 | 높이의 22~26% | 높이의 12~20%(13장이면 두 줄) |
| 2 | 바닥 | 손패 카드의 85% 크기, 낸 사람 쪽으로 치우침 | 판 가운데 약 30% 면적 | 폭의 80% 정사각형 |
| 3 | 차례·공약·기루다·프렌드 | 차례: 자리 판 빛 테두리 + 내 차례면 손패가 살짝 떠오름. 공약 등: 위쪽 고정 표시(HUD) | HUD 높이 40px | HUD 높이 44px |
| 4 | 각자 딴 점수 카드 | 자리 판 안 작은 카드 줄(무늬+숫자) | 자리 판 안 | 자리 판 안(장수가 많으면 숫자로 접기) |
| 5 | 돈 | 자리 판 구석 작은 글자(옵션) + 점수판 서랍 | 거의 없음 | 서랍에만 |

HUD에 넣는 것: 기루다 무늬와 공약 숫자(가장 크게), 주공 이름, 프렌드(카드 그림 / 초구 / 노프렌드 / 공개되면 이름), 트릭 진행(4/10), 아직 나오지 않은 점수 카드 수, 메뉴 단추. "남은 점수 카드 수"는 화면에 보이는 사실만으로 계산되므로 숨은 프렌드를 드러내지 않는다.

### 3.5 자리 판 구성

```
+-------------------------+
| (o) Name      *  >  #7  |   o: 머리글자 원(팀 색 테두리)  *: 주공  >: 차례  #7: 장수
| [AS][KD][10H]   +3      |   딴 점수 카드 작은 앞면, 넘치면 +n
| 1,230                   |   돈(옵션, 기본 끔)
+-------------------------+
```

- 팀 색은 원작처럼 **공개된 사람만** 바꾼다(주공·공개된 프렌드 = 여당 색). 공개 전엔 모두 같은 색이다.
- 차례: 자리 판 전체에 빛 테두리, AI면 테두리를 따라 도는 생각 중 표시. 원작의 이름 테두리보다 훨씬 굵게 보인다.
- 선(이번 트릭 첫 사람): 작은 `선` 배지.
- 선거 중 공약은 자리 판 옆 말풍선("♠14", "포기"). 원작처럼 앞선 후보 말풍선은 남기고 밀린 것은 흐리게 한다.
- 6·7마에서 탈락한 사람은 자리를 지우지 않고 흐리게 "탈락" 표시만 한다. 판 중간에 자리가 움직이면 헷갈리기 때문이다.
- 크기: 가로 화면은 폭 `clamp(120px, 12vw, 180px)`, 세로 폰은 `clamp(76px, 24vw, 112px)`. 7인 세로 폰에서는 점수 카드 줄을 숫자 배지로 접는다.

### 3.6 2~7인 자리 규칙

자리는 **판 영역 안의 타원 위 각도**로 정한다. 각도는 화면 좌표 기준(0° = 오른쪽, 90° = 아래, 각도가 커지면 화면에서 시계 방향)이다. 나는 항상 90°(아래)다. 아래 표는 "나부터 시계 방향으로 k번째 사람"의 각도다.

| 인원 | 1 | 2 | 3 | 4 | 5 | 6 | 원작과 비교 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 2 | 270 | | | | | | 같음(마주 보기) |
| 3 | 205 | 335 | | | | | 같음(양옆 위쪽) |
| 4 | 180 | 270 | 0 | | | | 같음(왼쪽·위·오른쪽) |
| 5 | 165 | 235 | 305 | 15 | | | 같음(옆 둘은 조금 아래, 위 둘) |
| 6 | 160 | 215 | 270 | 325 | 20 | | **다름**: 원작은 나를 오른쪽 아래로 옮겼지만, 내 손패가 가운데 있어야 하므로 나는 가운데에 두고 나머지 5명을 위쪽에 펼친다 |
| 7 | 150 | 195 | 240 | 300 | 345 | 30 | 같음(양옆 둘씩, 위 둘) |

- 반시계 방향 옵션을 켜면 각도를 `180 - a`로 뒤집는다(좌우 대칭).
- 아래쪽(각도 0~180 사이, 즉 내 쪽)에 있는 자리 판은 손패 영역 위쪽 경계를 넘지 않게 끌어올린다.
- 자리끼리 겹치면(7인 세로 폰) 타원 가로 반지름을 조금 키우고 자리 판 크기를 0.85배로 줄인다. 그래도 겹치면 점수 카드 줄을 접는다.
- 같은 각도를 바닥 카드 방향에도 쓴다(4.6절). 그래서 "자리 판 → 그 사람 바닥 카드 → 판 가운데"가 한 직선 위에 놓여, 누가 냈는지 눈으로 따라가기 쉽다.

### 3.7 모달 대신 판 위 패널

모든 진행 중 선택은 **판 가운데 패널**이나 **카드 옆 작은 선택지**로 받는다. 화면 전체를 어둡게 덮는 모달은 쓰지 않는다. 패널 안 선택지는 엔진 `legalActions`로 만든 것만 보여준다.

| 단계 | 위치 | 내용 | 원작 대응 |
| --- | --- | --- | --- |
| 선거(내 차례) | 판 가운데 패널(세로 폰은 바닥 자리 전체) | 무늬 줄(♠ ◆ ♥ ♣ 노기루다), 숫자 증감 단추(가능한 숫자만), [출마] [포기]. 지금 최고 공약과 내 이전 공약을 위에 표시 | `DGoal` 손패 위 상자 |
| 선거(남의 차례) | 같은 자리, 접힌 상태 | "P3 공약 생각 중", 최고 공약. 각자 공약은 자리 판 말풍선 | `FloatGoalDSB` |
| 당선 발표 | 판 가운데 띠 | "P2 당선 ♠14" 0.9초 뒤 접힘 | `DMasterDecl` |
| 바닥 카드 교환 | 판 가운데 패널 + 손패 | 바닥 카드 3장이 손패로 들어오며 "새" 표시. 손패를 누르면 그 카드가 패널의 **버릴 칸 3개**로 옮겨 간다(다시 누르면 돌아온다). 칸이 다 차야 [확정]이 켜진다. 접힌 "공약 바꾸기" 줄(무늬·숫자, 바꿀 때 필요한 조건을 글로 표시) | `DGoal` 특권 상자 + 손패 토글 |
| 프렌드 지정 | 판 가운데 패널 | 탭 [카드] [초구] [노프렌드] (규칙에 따라 [사람]). 카드 탭: 빠른 선택 칩(마이티, 조커, 기루다 A, 추천 카드) + 직접 고르기(무늬 줄 → 숫자 줄, 두 번 눌러 고르기). 고른 카드를 크게 미리 보여주고 [확정] | `DFriend` |
| 조커 선으로 내기 | 그 카드 바로 위 작은 선택지 | [♠][◆][♥][♣], 기루다 무늬를 강조. 바깥을 누르면 취소하고 카드가 손패로 돌아간다 | `DSelect` 커서 옆 |
| 조커콜 카드 선으로 내기 | 같은 자리 | [조커콜] [그냥 내기] | `DSelect` |
| 딜미스 | 판 가운데 패널 | 딜미스 선언 여부 | `DGoal`의 딜미스 처리 |
| 2마 카드 고르기 | 판 가운데 패널 | 보이는 카드 / 안 보이는 카드 중 하나 | `DSelect2MA` |
| 판 결과 | 판 가운데 큰 시트(바닥이 비었으므로 가려도 된다) | 승패, 점수 계산 과정, 돈 변화, [다음 판] | `DReport` |
| 점수판·전적 | 가로: 오른쪽 서랍 / 세로: 아래에서 올라오는 시트 | 이름, 돈, 전적 | `DScoreBoard` 도구 창 |
| 옵션·규칙 | 별도 화면(판 시작 전) | | property sheet |

패널 규칙:

- 패널 크기는 바닥 영역과 같다. 그래서 패널이 나타나도 자리 판과 손패는 움직이지 않는다.
- 패널이 뜰 때 바닥 카드가 남아 있으면 먼저 트릭 모으기가 끝난 뒤 뜬다(이벤트 큐 순서).
- 키보드: Enter는 확정, Esc는 선택지 닫기(원작 `Board.cpp:467-485`와 같다).
- 알림(조커콜!, 프렌드 공개 등)은 패널이 아니라 해당 자리 판 옆이나 바닥 위에 0.7초 정도 떴다 사라진다. 원작의 5초짜리 조커 상자(`Mighty.h:65`)는 너무 길다.

### 3.8 손패가 많을 때 (세로 폰, 13장)

세로 폰(폭 390, 양옆 여백 12px, 쓸 수 있는 폭 366px)에서 계산하면:

| 장수 | 한 줄일 때 카드 폭 | 간격 | 판단 |
| --- | --- | --- | --- |
| 10장 | 66px | 33px | 한 줄로 충분 |
| 13장 | 52px | 26px | 누를 폭이 너무 좁다(권장 최소 약 44px의 절반 남짓) |

그래서 다음 규칙을 쓴다.

1. 한 줄 간격이 `max(30px, 카드 폭 × 0.42)`보다 작아지면 **두 줄**로 나눈다. 위 줄 `ceil(n/2)`장, 아래 줄 나머지. 정렬 순서는 위 줄 왼쪽 → 오른쪽, 이어서 아래 줄.
2. 두 줄일 때 카드 폭은 7장 기준으로 다시 계산하고(최대 화면 폭의 20%), 두 줄은 카드 높이의 50%만큼 겹친다. 13장이면 카드 폭 78px, 간격 48px, 손패 전체 높이 약 164px(화면의 19%)다(계산).
3. 아래 줄 카드가 위 줄 카드의 아랫부분을 가린다. 위 줄도 숫자 모서리(위쪽)는 다 보인다.
4. 바닥 카드 교환이 끝나 10장이 되면 한 줄로 돌아가는 동작을 FLIP(처음·끝 위치를 재고 그 차이만 움직이기)으로 0.3초 안에 보여준다.
5. 가로 스크롤 손패는 쓰지 않는다. 안 보이는 카드가 생기기 때문이다.
6. 누르고 손가락을 손패 위에서 미끄러뜨리면 손가락 아래 카드가 커지며 떠오른다(훑어보기). 손을 떼면 그 카드가 골라진다. 좁은 간격에서도 정확히 고를 수 있다.

가로 화면은 13장이어도 카드 폭의 40% 이상 간격이 나오므로 한 줄로 둔다. 가로 손패는 아주 약한 부채꼴(카드마다 1~2°, 가운데가 조금 높게)을 넣을 수 있다. 세로 화면은 세로 공간을 아끼려고 평평하게 둔다.

진행 규칙:

- 엔진 이벤트는 큐에 넣고 차례로 재생한다. 게임 상태는 이미 다음으로 넘어가 있어도 된다(03의 원칙).
- 큐에 쌓인 이벤트가 3개를 넘으면 그동안 배속을 1.5~2배로 올려 따라잡는다. 원작이 늦을 때 프레임을 건너뛴 것과 같은 생각이다(`Board_SE.cpp:359-372`).
- 내 입력이 필요한 순간에는 큐를 먼저 다 비운다. 바닥이 정리되기 전에 낼 카드를 고르게 하지 않는다.
- 화면 크기가 바뀌면 날아가는 카드도 새 목표 좌표로 이어서 간다. 원작처럼 크기 변경을 잠그지 않는다.

### 3.10 조작 규칙

**공통**

- 내 차례가 아니면 손패를 살짝 낮추고(밝기 90%) 반응하지 않는다.
- 내 차례면 손패가 살짝 떠오르고, 낼 수 없는 카드는 **어둡게(밝기 45%, 채도 낮춤)** 한다. 원작은 마우스를 올려야 알 수 있었다.
- 낼 수 없는 카드를 누르면 카드가 좌우로 짧게 흔들리고 손패 위에 이유를 1.5초 보여준다(예: "♠를 따라 내야 합니다"). 이유 문장은 엔진이 돌려주는 거절 사유로 만든다.

**마우스**

- 낼 수 있는 카드 위에 올리면 카드 높이의 8%만큼 올라간다(원작 5%).
- **한 번 클릭으로 바로 낸다**(원작 그대로).
- 바닥 카드 교환 중에는 클릭이 "버릴 칸으로 보내기/돌려받기"다.

**터치**

- 기본은 **두 단계**: 한 번 누르면 골라져 카드 높이의 20%만큼 올라가고 조금 커진다(원작 선택 1/5과 같은 높이). 같은 카드를 다시 누르거나, 골라진 카드를 위로 밀면 낸다. 다른 카드를 누르면 고른 카드가 바뀐다. 빈 곳을 누르면 고르기를 푼다.
- **끌어서 내기**: 카드를 바닥 쪽으로 끌어 손패 위 경계에서 카드 높이의 절반 이상 올라간 곳에서 놓으면 낸다. 그보다 낮으면 제자리로 돌아간다.
- 훑어보기(3.8절 6번)로 좁은 간격에서도 고른다.
- 설정에 "한 번 탭으로 바로 내기"를 둔다(익숙한 사람용, 터치 기본값은 끔, 마우스는 늘 켬).
- 한 번 낸 뒤 0.25초 동안은 다른 입력을 받지 않는다(두 번 눌림 방지).

**키보드**

- 좌우 화살표로 낼 수 있는 카드 사이를 옮기고, Enter로 낸다. Esc는 선택지 닫기. 숫자 키로 패널 선택지를 고를 수 있게 한다.

**실수 방지 정리**

| 상황 | 막는 방법 |
| --- | --- |
| 낼 수 없는 카드 | 어둡게 + 눌러도 내지 않음 + 이유 표시 |
| 좁은 간격에서 옆 카드를 누름 | 터치 두 단계, 훑어보기, 13장 두 줄 |
| 조커를 선으로 냈는데 무늬를 잘못 고름 | 선택지 바깥을 누르면 취소, 카드가 손패로 돌아감 |
| 바닥 카드에서 버릴 카드를 잘못 고름 | 버릴 칸에서 다시 눌러 돌려받기, 3장이 다 차야 [확정] |
| 공약 숫자를 잘못 누름 | 증감 단추로 한 칸씩, [출마]를 눌러야 확정. 포기는 [포기] 한 번이면 되지만 다시 누를 수 없으므로 단추를 출마와 떨어뜨려 놓는다 |
| 프렌드 카드를 잘못 고름 | 고른 카드를 크게 보여준 뒤 [확정] |

## 4. 구현 규칙

### 4.1 CSS grid와 절대 좌표 중 무엇을 쓸까

**섞어 쓴다.**

- **바깥 틀(HUD, 서랍, 시트, 패널 안쪽 배치)은 CSS grid/flex로 한다.** 글자·단추가 많고 크기가 내용에 따라 바뀌는 곳이라 브라우저 배치가 낫다.
- **카드와 자리 판은 화면 전체를 덮는 한 장의 "무대" 층에 절대 좌표로 놓는다.** 이유:
  1. 카드는 손패 → 바닥 → 점수 줄처럼 영역을 넘나든다. grid 칸이 다르면 같은 카드라도 부모 요소가 바뀌어 이동을 이어 그리기 어렵다. 좌표계가 하나면 `transform: translate()`만 바꾸면 된다.
  2. 타원 위 자리, 낸 사람 쪽으로 치우친 바닥 칸, 겹친 손패 간격은 모두 계산식이다. grid로 흉내 내면 인원마다 템플릿이 늘어난다.
  3. 좌표를 순수 함수로 만들면 vitest로 화면 크기별 좌표를 확인할 수 있다.
- 카드는 캔버스가 아니라 DOM 요소(SVG 카드 그림)로 그린다. 53장 정도는 `transform`만 움직이면 충분히 부드럽고, 누르기 판정·접근성(포커스, 읽어 주기)을 브라우저가 해 준다.
- 카드마다 고정 `key`(카드 id)를 두고, 상태가 바뀌면 새 좌표로 옮겨 가게 한다. 영역이 바뀌어도 같은 요소가 움직인다.

### 4.2 좌표 함수

```
computeLayout(input) -> Layout

input:
  viewport: { width, height, safeArea: { top, right, bottom, left } }
  playerCount: 2..7
  mySeatIndex, clockwise
  handCount            // 내 손패 장수 (10, 13, 14 ...)
  phase                // 'bidding' | 'privilege' | 'friend' | 'trick' | 'result' ...
  settings             // 카드 크기 배율, 한 번 탭으로 내기 등

Layout:
  orientation: 'landscape' | 'portrait'
  hud:   Rect
  table: Rect                      // 자리 판들이 놓이는 영역
  center: Rect                     // 바닥 = 행동 패널 자리
  hand:  { rows: Rect[], card: Size, slots: Slot[] }   // 내 손패 칸 n개
  seats: { anchor: Point, plate: Rect, angle: number, scoreRow: Rect }[]
  trick: { card: Size, slots: Slot[] }                  // 자리마다 바닥 칸
  deck:  Slot                      // 덱·바닥 카드 위치 (= center 가운데)
Slot = { x, y, rotate, z }         // 카드 가운데 좌표
```

모든 좌표는 안전 영역을 뺀 무대 기준 px다. `ResizeObserver`로 무대 크기가 바뀔 때마다 다시 계산한다.

### 4.3 방향 판정과 영역 나누기

```
W, H = 안전 영역을 뺀 무대 폭·높이
g    = 여백 = clamp(8, min(W, H) * 0.02, 24)
orientation = (W / H >= 1.0) ? 'landscape' : 'portrait'
```

정사각형 근처(0.85 ~ 1.15)는 가로 규칙을 쓰되 손패 카드 크기를 높이 기준과 폭 기준 중 작은 쪽으로 정한다.

**가로**

```
hudH   = (H < 480) ? 0 : 40          // 낮은 화면은 HUD를 위쪽 자리 판 사이에 띄움
handH  = card.h * 1.0 + liftSpace     // liftSpace = card.h * 0.2 (골라서 올라가는 높이)
table  = { x: g, y: g + hudH, w: W - 2g, h: H - hudH - handH - 2g }
center = 가운데가 table 가운데에서 아래로 table.h * 0.06 내려간 사각형
         폭 = min(trickCard.w * 3.4, table.w * 0.42)
         높이 = min(trickCard.h * 2.4, table.h * 0.62)
```

**세로**

```
hudH   = 44
handH  = rows * card.h - (rows - 1) * card.h * 0.5 + liftSpace
table  = { x: g, y: g + hudH, w: W - 2g, h: H - hudH - handH - 2g }
center = 정사각형, 한 변 = min(table.w * 0.8, table.h * 0.45)
         가운데 y = table.y + table.h * 0.62  // 위쪽은 자리 판, 아래쪽은 바닥
```

행동 패널은 늘 `center` 사각형을 쓴다. 패널 내용이 넘치면 패널만 위로 늘리고(자리 판 아래 경계까지), 손패 쪽으로는 늘리지 않는다.

### 4.4 카드 크기

카드 비율 `r = 높이 / 폭`은 카드 그림 파일 비율을 쓴다(일반 카드면 약 1.4).

**내 손패 (한 줄)**

```
usableW = W - 2g
minStep(cw) = max(30, cw * 0.42)                  // 터치 기준. 마우스만 쓰면 max(18, cw * 0.28)
cw_byWidth  = usableW / (1 + 0.55 * (n - 1))      // 간격을 카드 폭의 55%로 잡았을 때
cw_byHeight = (가로) H * 0.24 / r  |  (세로) W * 0.2
cw = clamp(min(cw_byWidth, cw_byHeight), 48, 200)  // (값, 최소, 최대)
step = min(cw * 0.75, (usableW - cw) / (n - 1))
if (세로 && step < minStep(cw)) -> 두 줄로 (4.7절)
```

**바닥 카드**: 가로는 손패 카드의 85%, 세로는 `center` 한 변의 28%와 손패 카드 중 작은 쪽.

**자리 판 안 점수 카드**: 높이 = 자리 판 높이의 32%. 줄에 다 안 들어가면 겹치고, 그래도 넘치면 `+n`.

### 4.5 자리 좌표

```
C  = table 가운데 (가로) / (table.x + table.w/2, table.y + table.h * 0.42) (세로)
Rx = table.w / 2 - plate.w / 2
Ry = (가로) table.h / 2 - plate.h / 2
     (세로) table.h * 0.36
a_k = 3.6절 표의 각도 (반시계 옵션이면 180 - a_k)
anchor_k = C + (Rx * cos a_k, Ry * sin a_k)
plate_k  = anchor_k 가운데에 놓은 plate 크기 사각형을 table 안으로 밀어 넣은 것
```

- 각도 표는 상수 데이터로 둔다(원작의 자리 표처럼). 공식으로 만들면 3인·6인처럼 손으로 다듬은 값을 표현하기 어렵다.
- 밀어 넣은 뒤 자리 판끼리 겹치면 `Rx`를 table 폭 한도까지 늘리고, 그래도 겹치면 plate를 0.85배로 줄인다.
- 내 자리 anchor는 손패 위 경계 가운데 `(W/2, hand.top)`로 둔다. 바닥 칸 방향과 "내가 낸 카드가 출발하는 곳"에 쓴다.

### 4.6 바닥 칸 좌표

자리마다 바닥 칸 하나를 둔다. 같은 각도로 `center` 안의 작은 타원 위에 놓는다.

```
Tc = center 가운데
Tx = center.w / 2 - trickCard.w / 2
Ty = center.h / 2 - trickCard.h / 2
slot_k = Tc + (Tx * cos a_k, Ty * sin a_k)     // 나는 a = 90 -> center 아래쪽 끝
rotate_k = (카드 id로 정한 -5° ~ +5°)          // 같은 판을 다시 재생해도 같은 각도
z = 이번 트릭에서 낸 순서
```

- 원작의 "가로 5단계 × 세로 5단계" 칸을 연속 각도로 바꾼 것이다(`Board_Layout.cpp:338-354`).
- 7인이면 이웃 칸이 겹친다. 겹침 허용 한도는 카드 폭의 40%까지로 하고, 넘으면 `Tx`, `Ty`를 10% 키운다. 그래도 넘치면 바닥 카드 크기를 0.9배로 줄인다.
- 2인은 위·아래 두 칸뿐이라 `Ty`를 카드 높이의 60%로 줄여 가운데로 모은다.

### 4.7 손패 칸 좌표

**한 줄**

```
totalW = cw + step * (n - 1)
x0     = W / 2 - totalW / 2 + cw / 2
slot_i = (x0 + step * i, hand.bottom - ch / 2, rotate: fan(i))
fan(i) = (가로) (i - (n-1)/2) * min(1.5°, 16° / n), y는 가운데가 몇 px 높게
         (세로) 0
```

**두 줄** (세로, 4.4에서 넘쳤을 때)

```
top    = ceil(n / 2) 장,  bottom = n - top 장
cw     = min(W * 0.2, usableW / (1 + 0.55 * (top - 1)))
step   = (usableW - cw) / (top - 1)
윗줄 y = hand.top + ch / 2
아랫줄 y = 윗줄 y + ch * 0.5
아랫줄 x는 윗줄과 같은 간격으로 가운데 정렬
z: 아랫줄이 위
```

- 상태: `selected`면 `y - ch * 0.2`, 마우스 올림이면 `y - ch * 0.08`, 내 차례가 아니면 `y + ch * 0.06`.
- 누르기 판정은 각 카드의 **보이는 부분**(다음 카드에 가리지 않은 띠 + 위쪽)으로 한다. DOM 요소는 겹치므로 `z`가 높은 카드가 먼저 받는다. 원작도 오른쪽 카드부터 검사했다(`Board_Layout.cpp:571-578`).

### 4.8 덱·바닥 카드·점수 줄 좌표

- 덱과 바닥 카드: `center` 가운데. 선거 중에는 바닥 카드 3장을 뒷면으로 살짝 펼쳐 둔다(원작도 진행 중이 아닐 때 가운데 덱을 그렸다, `Board_Draw.cpp:304-312`). 행동 패널이 뜨면 패널 위쪽 귀퉁이로 작게 옮긴다.
- 나눠 주는 카드의 목적지: 남은 자리 판 가운데, 나는 손패 칸.
- 점수 줄: 자리 판 안 `scoreRow` 사각형. 카드 j의 x = `scoreRow.x + j * min(miniW * 0.7, (scoreRow.w - miniW) / (m - 1))`.
- 여당이 딴 카드와 점수 아닌 카드의 목적지: 자리 판 가운데에서 크기 0으로. 원작의 "화면 밖"(`CR_HIDDEN`) 대신이다.

### 4.9 크기 변화와 애니메이션

- 무대 크기가 바뀌면 `computeLayout`을 다시 부르고 모든 카드에 새 목표를 준다. 날아가던 카드는 지금 위치에서 새 목표로 이어서 간다.
- 회전(가로 ↔ 세로)처럼 크게 바뀔 때는 이동 대신 0.2초 흐려졌다 나타나기로 바꾼다. 모든 카드가 한꺼번에 날아다니면 어지럽기 때문이다.
- 폰 가로에서 주소창이 접혔다 펴지는 작은 변화(높이 ±60px)는 0.15초 안에 조용히 따라간다.

### 4.10 확인 방법

- `computeLayout`은 순수 함수이므로 대표 화면 크기(1920×1080, 1280×720, 1024×768, 844×390, 390×844, 360×740)와 인원 2~7, 손패 10·13장 조합으로 vitest를 만든다.
- 확인할 것: 자리 판끼리 겹치지 않는다, 자리 판이 손패·HUD와 겹치지 않는다, 손패가 화면 밖으로 나가지 않는다, 터치 기준 간격(30px 이상)을 지킨다, 바닥 칸이 `center` 안에 있다, 나의 바닥 칸이 가장 아래에 있다.
- 실제 화면 확인은 Playwright로 같은 화면 크기에서 화면을 찍어 비교한다.
