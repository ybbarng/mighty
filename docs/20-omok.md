# 20. 오목 (2026-10-28 작성)

게임 센터의 첫 공개 게임([18](./18-game-center-plan.md) 7절). 마이티·하트보다 누구나 아는 게임으로 연결 인프라(신호 서버·WebRTC·TURN)를 시험받는다.
모든 게임 공통 원칙(18 5절): PC·휴대폰 화면을 함께 맞추고, 컴퓨터를 여러 단계로 둔다.

## 1. 규칙

한국에서 흔히 두는 오목은 지역·모임마다 금지 수가 다르다. 그래서 규칙을 고를 수 있게 하고 기본값을 하나 둔다.

| 규칙 | 이기는 것 | 금지 수 | 쓰임 |
|---|---|---|---|
| **일반(기본)** | 정확히 다섯 | 흑·백 모두 3·3(열린 삼 둘을 한 번에) | 학교·동네에서 흔한 규칙 |
| 자유 | 다섯 이상 | 없음 | 가장 단순. 흑이 크게 유리하다 |
| 렌주 | 흑: 정확히 다섯 / 백: 다섯 이상 | 흑만 3·3, 4·4, 여섯 이상(장목) | 대회 규칙(오프닝 규정은 넣지 않는다) |

- 판은 15×15. 흑이 먼저 둔다. 판이 다 차면 비긴다.
- 금지 수는 둘 수 없다(누르면 "3·3 금지" 같은 알림). 금지 자리는 내 차례에 판에 작은 ×로 보여 준다(설정으로 끌 수 있다).
- 금지 판정은 렌주 규칙의 정의를 따른다: "열린 삼"은 한 수 더 두면 **금지가 아닌** 열린 사가 되는 삼이다(재귀 판정).
  일반 규칙의 3·3도 같은 판정을 쓴다.
- 여러 판: 판마다 흑백을 바꾼다. 점수는 이긴 판 수.
- 무르기: 혼자 할 때만(컴퓨터 상대). 내 수와 컴퓨터 수를 한 번에 되돌린다. 온라인은 상대가 받아 주면(나중).
- 시간(2026-10-28 사용자 요청, 온라인 다음에): 바둑처럼 사람마다 기본 시간 + 초읽기. 고르는 것: 없음(기본) / 빠른(기본 3분 + 30초 3번) / 보통(기본 10분 + 30초 3번).
  내 차례에만 내 시계가 줄고, 기본 시간을 다 쓰면 초읽기로 넘어가 한 수를 그 안에 둬야 한다. 초읽기를 다 쓰면 진다(시간패).
  온라인에서는 방장 기기가 시계를 재고 시간이 다 되면 엔진에 `timeout` 행동을 넣는다(판 끝 다시 두기로 검증할 수 있게 행동으로 남긴다).
  남은 시간은 방장이 수마다 화면에 실어 보내고, 참가자 화면은 받은 값에서 거꾸로 센다. 컴퓨터 상대일 때는 내 시계만 쓴다.

## 2. 화면(PC·휴대폰)

- 판은 화면 짧은 쪽에 꽉 차게. 휴대폰 세로 360px이면 칸이 약 22px.
- **PC**: 마우스를 올리면 그 자리에 반투명 돌, 누르면 둔다. 키보드 화살표로 옮기고 Enter로 둔다.
- **휴대폰**: 손가락이 돌을 가려 잘못 두기 쉬워서 **두 번 눌러 둔다**: 처음 누르면 반투명 돌과 십자선이 생기고, 같은 자리를 다시 누르거나 "여기 두기"를 누르면 둔다. 다른 자리를 누르면 반투명 돌이 옮겨 간다.
- 마지막 수는 점으로 표시, 이긴 다섯 줄은 선으로 잇는다.
- 판 옆(가로) 또는 위아래(세로)에 두 사람 이름·돌 색·차례 표시, 무르기·기권·다시 하기.

## 3. 컴퓨터

| 단계 | 방법 | 느낌 |
|---|---|---|
| 입문 | 이기는 수·막아야 할 다섯은 본다. 그 밖에는 돌 근처에서 점수 높은 자리 몇 곳 중 무작위 | 처음 두는 사람도 이길 수 있다 |
| 중수 | 자리마다 공격·수비 모양 점수(열린 삼·막힌 사·열린 사 등)를 더해 가장 좋은 자리 | 열린 삼을 놓치지 않는다 |
| 고수 | 모양 점수로 후보를 추린 알파베타 탐색(깊이 4~6) + 사·삼으로 몰아붙이는 승리 수순(VCF) 찾기 | 웬만한 사람은 이기기 어렵다 |

- 모두 금지 수를 지킨다(엔진의 `legalMoves`를 쓴다).
- 다시 보기 해설: 고수 점수로 그 수를 견준다(`KitReview.explain`).
- 2026-10-28 잰 결과(`pnpm -C packages/omok-ai bench`, 일반 규칙, 흑백 번갈아 20판): 중수가 입문에게 20승, 고수(깊이 4, 후보 9)가 중수에게 20승.
  고수 한 수는 맥북에서 가운데 57ms·가장 길게 119ms. 금지 판정을 후보 앞 순위부터 필요한 만큼만 해서 10배 줄였다.
  모양 점수는 다섯 칸 창마다 상대 돌이 없으면 내 돌 수에 따라 1·12·160·3000·100만.

## 4. 구조

- `packages/omok-engine`: 순수 함수. `createMatch`, `step`, `legalMoves`, `forbiddenReason`, `winLine`, 규칙 부호화.
- `packages/omok-ai`: 세 단계 봇(`KitBot<View, Action>`).
- `apps/web/src/omok/`: 화면, `GameKit` 구현(`omokKit`), 등록부에 `{ id: "omok", path: "/omok" }`.
- 온라인은 지금 `HostRoom`·`GuestRoom`을 그대로 쓴다. 완전 공개 게임이라 멘탈 포커가 없고, 판 끝 검증은 기록을 다시 둬 보는 것(`replay`)뿐이다.
- 새 패키지 둘은 `Dockerfile`의 package.json COPY 줄에 넣는다.

## 5. 설계 다섯 질문(데이터 계약: 상태·행동·규칙 부호)

1. **데이터의 뜻·연결·책임**
   - 상태 `OmokState`: `rules`, `board`(길이 225 배열, 0 빈칸·1 흑·2 백), `moves`(둔 자리 차례대로), `turn`(1|2), `seats`(자리 → 돌 색, 판마다 바뀜), `round`, `score`, `result`(진행 중 | 이김(색·다섯 줄) | 비김 | 기권).
   - 행동 `OmokAction`: `{ type: "place", at }`(at = y*15+x) · `{ type: "resign" }` · `{ type: "next" }`(다음 판) · `{ type: "retire" }`(끊긴 사람 끝내기). 무르기는 혼자 할 때 화면이 기록을 줄여 `replay`로 다시 만든다(엔진 행동이 아니다 → 온라인에 무르기가 새지 않는다).
   - 화면 `OmokView` = 상태 그대로 + `mySeat`. 감출 것이 없다.
2. **꼭 지킬 규칙의 보장**: 둘 수 있는가·이겼는가·금지인가는 엔진 한 곳(`step`)만 판정한다. 화면과 봇은 엔진 함수를 부른다. 온라인 참가자 수도 방장 엔진이 `step`으로 거른다.
3. **사람과 AI가 찾아 쓰기**: 자리 번호는 `y*15+x`, 사람에게는 "H8"처럼 글자+숫자로 보인다(가로 A~O, I 포함, 세로 1~15 아래부터). 기록 내보내기도 이 표기.
4. **요구가 바뀌면**: 판 크기(19×19)·새 규칙은 `rules`에 넣고 부호화에 칸을 더한다. 바둑·장기·체스는 각자 엔진이지만 화면 조각(판, 두 번 눌러 두기, 차례 표시)은 오목에서 먼저 만들어 공용으로 뺀다.
5. **대안과 근거**: 판을 비트보드로 — 빠르지만 읽기 어렵고, 15×15는 배열로도 고수 탐색이 충분히 빠르다(필요하면 봇 안에서만 바꾼다). 금지 수를 화면에서 판정 — 온라인에서 어긋날 수 있어 버렸다.
