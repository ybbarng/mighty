# 12. 모의 침투 점검 (2026-10-21)

사용자 요청으로 서브에이전트에게 "소스 코드를 다 가진 공격자 한 명이 자기 프로그램을 고쳐 유리하게 이끌 방법"을 찾게 했다(나머지 참가자는 모두 정상 프로그램, 담합 없음). 보고서의 항목마다 **공격을 실제로 해 보는 시험**을 먼저 만들어 정말 통하는지 확인하고(시험 실패 = 공격이 통함), 고친 뒤 같은 시험이 통과하는지 봤다. 시험: `apps/web/src/net/attacks.test.ts`, `room.test.ts`, `packages/engine/src/robustness.test.ts`.

| 항목 | 공격 | 확인 | 처리 |
|---|---|---|---|
| A1 | 방장이 시작 알림에서 참가자 약속을 빼고 자기 값만으로 시드를 골라 원하는 패 받기 | **통함** — 참가자는 자기 약속이 없으면 확인을 건너뛰었다 | 참가자가 시작 알림에 자기 약속이 그대로 있는지 확인. 판 끝 공개에 실제 쓴 약속 목록을 넣고, 시작 때 것과 같은지·내 것과 방장 것이 있는지 확인 |
| A2 | 방장이 판 끝 기록을 공개하지 않고 나가기(모든 조작이 검증을 피함) | **통함** — 아무 경고가 없었다 | 게임을 했는데 기록 없이 방장이 나가면 "검증하지 못했다"를 실패로 알림 |
| A3 | 방장이 참가자가 낸 카드를 다른 합법 카드로 바꿔 넣기 | **통함** — 기록과 화면이 서로 맞아 검증을 통과했다 | 참가자가 보낸 행동을 적어 두고 기록 속 내 자리 행동과 대조(끊긴 적이 있으면 빠짐·바뀜만 확인) |
| A4 | 방장이 모든 패를 보면서 컴퓨터 자리를 조종 | **통함** | 대기실에 컴퓨터 실력을 알리고, 컴퓨터 수에 표를 달아 기록. 참가자가 같은 컴퓨터·같은 난수로 다시 계산해 대조. 정직한 판이 통과하는 것도 시험 |
| A5 | 방장이 모든 패 보기 | 설계상 그대로 | 한계로 명시(멘탈 포커 필요) |
| A6 | 방장이 중간 화면 꾸며 보내기 | 이미 막음 | 받은 화면 전부 대조(앞선 커밋) |
| A7 | 방장이 남의 이름으로 채팅·`[검증]` 줄 꾸미기 | 통함(일부) | 시스템 줄(자리 −1)은 네트워크에서 받지 않음. 방장의 대화 위조는 한계로 명시 |
| B1 | 새로고침한 참가자의 토큰을 엿들어 방장에게 다시 보내 자리 빼앗기 | **통함** — 입장 요청이 방 안 모두에게 토큰째로 갔다 | 토큰 대신 SHA-256(토큰·받는 사람 연결 아이디) 증명만 보냄. 방장은 자기 연결 아이디로 확인하므로 엿들은 값을 다른 데서 못 씀 |
| B2 | 한 연결이 이름만 바꿔 여러 자리 차지 | **통함** — 동시에 온 요청을 따로 처리했다 | 입장 요청을 하나씩 처리하고, 이미 앉은 연결이면 같은 자리를 다시 알림 |
| B3 | 남의 자리로 "검증 실패"를 알리거나 거짓 실패로 게임 무효 만들기 | 통함 | 알림은 대기실의 자리별 연결 아이디와 맞아야 받음. 게임 무효 표시는 **내 기기의 검증**만, 남의 실패는 "주장"으로 채팅에 표시 |
| B4 | 다른 참가자에게 가짜 방장 노릇(가짜 환영·내보내기·대기실) | 통함(HEAD) | 방장 서명(앞선 커밋). 확인 전에는 내보내기·대기실·자리 없음·거절 메시지를 받지 않음 |
| B5 | 아무 글이나 알림으로 띄우기, "자리 없음" 위조 | 통함 | 방장으로 확인한 연결에서만 받음 |
| B6 | 참가자가 `retire`로 게임 강제 종료 | **통함** | 온라인 참가자 행동에서 그만두기를 막음(`guestMayAct`) |
| B7 | 마이티 엔진이 모르는 행동을 받아 기록을 부풀리기 | **통함** — switch에 default가 없었다 | 엔진이 모르는 행동을 거절. 2마 고르기 번호도 0·1만 |
| B8 | 약속과 다른 값을 내서 시작 막기 | **통함** — 시작이 예외로 멈췄다 | 값을 받을 때 약속과 맞는지 확인하고, 틀리면 안 낸 것으로 쳐서 시드에서 뺌 |
| B9 | `slot`(손패 몇 번째)으로 남의 무늬 장수 짐작 | 통함 | **그대로 둠**: 사용자가 원한 기능(뽑는 위치로 짐작하기). 오프라인에서 보는 것과 같은 정보로 봄 |
| (c) | 링크만 알고 자리 없는 사람이 대기실·채팅·판 끝 기록 엿듣기 | 통함 | 방장이 "모두에게" 보낼 때도 앉은 참가자에게만 하나씩 보냄 |
| (d) | 릴레이를 지켜보며 6글자 방 코드 맞히기 | 확인 필요(가능성 높음) | 방 코드를 16글자(약 80비트)로 늘림. 방장 지문이 함께 있어 코드만으로는 방장 행세도 못 함 |

남은 것:
- A5(방장이 패를 봄), A7(방장의 대화 위조)은 지금 구조의 한계다. 멘탈 포커, 참가자별 서명이 필요하다.
- 판 끝 검증은 게임이 끝날 때 한 번이다. 판마다 약속·공개를 새로 하면 더 일찍 잡을 수 있다.
- 확인 필요: Trystero에서 남의 연결 아이디를 흉내 낼 수 있는지, Nostr 이벤트에 방 주제 해시가 공개 태그로 실리는지(방 코드를 늘려 위험은 줄였다).
