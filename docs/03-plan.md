# 03. 되살리기 계획

## 목표

1. **원작 Mighty Network의 느낌을 살린 웹 마이티.** 규칙 옵션과 옵션 공유를 지원한다.
2. **혼자서도, 둘이서도 할 수 있게.** 빈자리는 적당한 실력의 AI가 채운다.
3. 기본은 5마. 6마·7마(주공이 한 명을 죽여 5마로 줄임)와 2~4마는 옵션으로 둔다.
4. 나중 확장: 온라인 멀티 → 안드로이드/iOS 네이티브 → 인터넷 없이 BLE/로컬 네트워크 대전 → 다른 게임에도 쓸 수 있는 통신 계층.

첫 번째 결과물은 **서버 없는 웹게임**(사람 1명 + AI 4명, 같은 화면을 돌려 쓰는 핫시트)이다. 확장은 코드 구조로만 대비하고 지금 만들지는 않는다.

## 결정 1: 기존 코드를 고칠까, 새로 만들까 → 새로 만든다

| 기준 | 기존 코드 발전 | 새로 만들기 |
| --- | --- | --- |
| 라이브러리 | CRA 3 → 지원 종료, React 16, boardgame.io 0.31 → 0.50에서 게임 정의 문법이 전부 바뀜. 올리는 것 자체가 다시 쓰기 | 처음부터 최신 |
| 규칙 엔진 | UI가 게임 진행을 몰고 가는 구조, 5인 고정, 옵션 없음, 확인된 버그 10건 | 원작 옵션 59개를 처음부터 반영 |
| AI | 엔진이 boardgame.io 안에 있어 화면 없이 대량 시뮬레이션하기 어렵다 | 순수 함수 엔진이라 AI가 바로 쓴다 |
| 남길 가치 | 규칙 판정 함수의 아이디어, 한국어 문구, 카드 이미지, UI 흐름 | 이것들은 새 코드로 옮긴다 |

코드량이 2,400줄 정도로 작고, 남길 가치가 있는 것은 "코드"보다 "지식과 자산"이다. 기존 코드는 git 기록(`master`, 태그 `legacy-2019`)에 그대로 두고 참고만 한다.

## 결정 2: boardgame.io를 계속 쓸까 → 쓰지 않는다

- npm 릴리스가 2022년에 멈췄다. 2026년 정비가 릴리스로 이어질지 알 수 없다.
- 2019년에 막혔던 문제 대부분(`invalid stateID`, `TurnOrder.ANY_ONCE`, phase 전환 무한 루프)이 "프레임워크의 턴/phase 모델에 게임을 맞추는" 데서 왔다.
- 마이티는 "공약 → 교환 → 프렌드 → 10트릭 → 점수"로 흐름이 단순하다. 직접 만든 상태 기계가 더 짧고 명확하다.
- 이 프로젝트에 필요한 기능(숨긴 정보, 결정적 난수, 봇)은 엔진 안에서 작게 만들 수 있다. 온라인은 나중에 [02-research.md](./02-research.md) 5절의 선택지 중에서 고른다.

## 구조

```
mighty/
├─ packages/
│  ├─ engine/   @mighty/engine — 규칙 엔진. 외부 의존성 없음, DOM/네트워크 모름
│  └─ ai/       @mighty/ai     — 컴퓨터 플레이어. engine에만 의존
├─ apps/
│  └─ web/      Next.js 정적 웹앱. 화면 + 로컬 대국 진행(LocalMatch)
└─ docs/
```

의존 방향은 `web → ai → engine` 한 방향뿐이다. engine은 아무것도 모른다.

### engine 설계 원칙

1. **순수 함수.** `step(state, seat, action) → { state, events } | { error }`. 입력 상태를 바꾸지 않는다.
2. **직렬화 가능.** 상태와 행동은 모두 JSON이다. 난수 생성기 상태도 상태 안에 들어 있어 `(규칙, 시드, 행동 목록)`만 있으면 판 전체를 다시 재생할 수 있다. → 저장/불러오기, 버그 재현, 온라인 동기화, 리플레이.
3. **화면은 이벤트로.** 셔플·딜·카드 냄·트릭 승리·프렌드 공개 같은 연출은 `step`이 돌려주는 `events`로 전달한다. 기존 코드처럼 게임 상태에 `prevMove`를 넣지 않는다. 애니메이션이 게임 진행을 막지 않는다.
4. **숨긴 정보는 엔진이 가린다.** `viewOf(state, seat)`가 그 자리에서 보이는 정보만 돌려준다. AI와 화면은 `PlayerView`만 받는다(원작 AI처럼 남의 패를 훔쳐보지 않는다).
5. **할 수 있는 행동 목록.** `legalActions(state, seat)`를 엔진이 제공한다. 화면은 버튼 활성화에, AI는 탐색에 같은 함수를 쓴다. 규칙이 UI에 새어 나가지 않는다.
6. **규칙은 데이터.** `RuleSet`은 원작 `CRule`의 59개 항목을 그대로 따른다. 원작 규칙 문자열과 서로 변환할 수 있어 기본 규칙 14종과 사용자 규칙을 공유할 수 있다.

### 확장 지점

```
          ┌───────────────── MatchHost (인터페이스) ─────────────────┐
화면 ───▶ │ submit(action) / subscribe(view, events)                 │
          └──────────────────────────────────────────────────────────┘
               ▲ 지금: LocalMatch      (브라우저 안에서 engine + AI)
               │ 나중: RemoteMatch     (WebSocket → 서버의 engine)
               │ 나중: PeerHostMatch   (BLE/로컬 네트워크, 방장 기기의 engine)
```

화면은 `MatchHost`만 알고, 누가 엔진을 돌리는지는 모른다. 온라인·BLE를 붙일 때 화면과 엔진은 그대로 두고 `MatchHost` 구현만 늘린다. 이 인터페이스는 처음엔 `apps/web` 안에 두고, 두 번째 구현이 생길 때 `packages/match`로 떼어낸다(쓰는 곳이 하나일 때 범용화하지 않는다).

네이티브 앱은 engine/ai를 그대로 쓰고 화면만 React Native(Expo)로 다시 만들거나, 웹을 Capacitor로 감싸는 두 길이 있다. BLE는 iOS Safari에서 Web Bluetooth가 안 되므로 네이티브가 필요하다. 그때 정한다.

## 화면 방향

- 원작 화면을 그대로 복원하지 않는다. 원작에서는 용어와 진행 흐름만 가져온다.
- **둘러앉은 원 테이블** 배치: 내 자리는 아래, 나머지는 인원수에 맞춰 원을 따라 둔다. 바닥 카드는 낸 사람 쪽에서 가운데로 모인다.
- 현대적인 화면: 카드를 나눠 주고, 내고, 트릭을 가져가는 동작에 자연스러운 애니메이션을 넣는다. 애니메이션은 엔진의 `events`를 받아 화면이 따로 재생하고, 게임 진행을 막지 않는다.
- 직관적인 조작: 낼 수 있는 카드만 밝게 표시한다. 클릭/탭 한 번으로 내고, 조커 무늬 지정·조커콜 여부 같은 선택은 카드 옆에 바로 뜨는 작은 선택지로 받는다. 공약·프렌드 지정은 엔진의 `legalActions`로 고를 수 있는 것만 보여준다.
- 휴대폰 세로 화면에서도 할 수 있어야 한다.

## 튜토리얼

언어 학습 앱처럼 짧은 레슨을 하나씩 쌓아 가고, 중간에 확인 퀴즈와 작은 실전 미션을 둔다. 다 끝내면 AI와 한 판을 끝까지 할 수 있는 수준이 목표다.

| 단원 | 익히는 것 | 확인 방식 |
| --- | --- | --- |
| 1. 목표 | 여당(주공+프렌드) 대 야당, 점수 카드(10·J·Q·K·A) 20장 중 공약만큼 가져가면 여당 승리 | 퀴즈: 이 트릭에서 점수 카드는 몇 장? |
| 2. 트릭 | 선 무늬 따라내기, 높은 카드가 이긴다, 이긴 사람이 다음 선 | 미션: 정해진 패로 트릭 3개 이기기 |
| 3. 기루다 | 기루다는 다른 무늬를 이긴다, 선 무늬가 없을 때만 낼 수 있다 | 퀴즈: 누가 이 트릭을 이기나? |
| 4. 마이티와 조커 | 가장 센 두 장, 언제든 낼 수 있다, 조커 무늬 지정, 첫·막 트릭 예외 | 미션 |
| 5. 조커콜 | 조커콜 선언과 조커를 끌어내는 법 | 미션: 조커콜로 조커 잡기 |
| 6. 공약 | 출마, 무늬와 숫자, 노기루다, 포기 | 퀴즈: 이 패로 얼마를 부를까? (정답 범위) |
| 7. 주공 | 키티 받기, 3장 버리기, 공약 바꾸기(+2 규칙) | 미션 |
| 8. 프렌드 | 카드 프렌드, 초구, 노프렌드, 프렌드가 드러나는 순간 | 퀴즈 |
| 9. 점수 계산 | 기본 이동량, 런·노기루다 배수, 주공 2배 | 퀴즈 |
| 10. 실전 | AI와 힌트를 켠 채 한 판 | 끝까지 하기 |

구조상 필요한 것:

- **정해진 패로 판 시작**: 엔진이 시드 대신 손패·키티를 직접 받아 판을 시작할 수 있게 한다(`createRound`에 시나리오 입력). 레슨과 미션은 이 시나리오 데이터로 만든다.
- **용어 사전 데이터**: 기루다, 주공, 프렌드, 초구, 조커콜, 런, 백런, 딜미스 등. 게임 화면의 도움말과 튜토리얼이 같은 데이터를 쓴다.
- **진행 기록**: 끝낸 단원과 퀴즈 결과를 브라우저에 저장한다.
- 튜토리얼 시나리오도 엔진 테스트로 확인한다(예: "이 패로는 조커콜로 조커를 잡을 수 있다").

## 위험 요소

- **효과음 저작권**: 지금 효과음은 원작에서 가져온 것이고 출처가 불분명하다. M4 전에 무료 라이선스 효과음으로 바꾼다.
- **카드 이미지**: 기존 SVG의 출처(deck-of-cards, MIT로 알려져 있다)를 M4 전에 확인한다.
- **지역 규칙의 끝없는 변형**: 원작 옵션 59개를 기준선으로 삼고, 그 밖의 하우스룰은 요청이 있을 때 옵션으로 추가한다.
- **AI 수준**: "적당한 실력"이 목표다. 1단계 봇을 먼저 내고, 실제로 해보며 2단계에 투자할지 정한다.
