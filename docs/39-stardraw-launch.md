# 39. 하늘의 별 따기 출시 준비 — 사용자 여정과 준비 완료 신호

2026-10-31 사용자와 정함. 회사 메신저에 링크를 올려 회사 사람들을 부르기 전에, 그 사람들이 겪을 여정을 처음부터 끝까지(1등 당첨 뒤 확인까지) 따라가며 막히는 곳이 없고 **상품과 관련된 어뷰징이 불가능**하다는 것을 확인한다. 이 문서의 점검표가 모두 초록이면 "준비 완료"다.

공개 저장소라 회사 이름·도메인·공지 원문은 적지 않는다(소속 도메인은 비공개 서버 설정에만, 10-31 규칙).

## 1. 공지 요지(사용자가 쓸 글의 뼈대)

- 우주국장(운영자)이 회사 사람들에게: 패스키로 참여하는 이벤트, 45개 별 중 6개를 정확히 맞히면(1등) 우주국장이 커피를 산다.
- 기간 5년, 응모와 추첨은 매시간.
- 응모와 추첨 과정은 공개하고, 어뷰징이 불가능하게 만들었다.

공지에 쓰는 약속은 모두 이 문서에서 확인한 것만 쓴다. 특히 "매시간"(지금 시험 장부는 20분 회차, 정식 일정표는 1시간으로 잡아야 한다)과 "어뷰징이 불가능"(3절의 범위)을 지킨다.

## 2. 사용자 여정과 점검

각 단계는 세 가지로 확인한다: **자동**(화면 시험·단위 시험, CI), **실기기**(사용자 또는 동료가 실제 폰·PC로), **운영**(운영 서버·공개 장부에서 읽기로). 칸이 모두 채워져야 그 단계가 초록이다.

## 3. "어뷰징이 불가능"의 범위와 남은 일

공지의 약속은 **"커피(1등 상품)를 부정하게 받을 수 없다"**로 한정한다. 상품이 걸리지 않은 재미용 응모는 패스키를 여러 개 만들어 여러 장 낼 수 있다(P5, 막을 수 없고 상품과 무관하므로 감수). 상품 쪽에서 막아야 할 길과 상태:

**기준(사용자 2026-10-31)**: 어뷰징은 "본인의 허락 없이 남의 몫을 가져가는 것"이다. 본인이 허락한 양보·대리는 막지 않는다. 대신 허락 없이 되는 길(취약점)은 모두 막는다.

| 길 | 상태 | 남은 일 |
|---|---|---|
| 한 사람이 회차당 여러 장으로 상품 확률 높이기 | 소속 증서 1개 = 회차당 1장, 같은 증서 두 장이면 둘 다 제외(구현됨) | — |
| 동료가 건네준 복구 코드(소속 증서)로 여러 장 | 받아들임(사용자 2026-10-31: 동료가 허락한 일이고 효과가 작다) | 허락 없이 남의 복구 코드를 얻는 길이 있는지 찾아 막기(기기 저장소에 평문, 화면에 보이는 복구 코드, XSS, 공용 PC) |
| 회사 계정을 여러 개 가진 사람이 계정마다 증서 | 받아들임(사용자: 계정이 아주 많을 수 없다) | 필요해지면 직원 명단·이메일을 미리 정해 그 안에서만 발급(입·퇴사마다 손으로 고쳐야 함) |
| 퇴사한 사람이 남은 자격 기간 동안 계속 상품 대상 | 해법 정함(사용자 2026-10-31): 커피를 주려면 당첨자와 연락해야 하고 그때 누군지 알게 되므로, 그 자리에서 지금 직원인지 확인한다 | 당첨 확인 절차(10단계)에 "직원인지 확인"을 운영자 할 일로 적기 |
| 운영자(서버 데이터를 읽은 사람)가 증서를 몰래 더 만들기 | 막히지 않음(P10) | 받을 때 묶기로 대부분 막힘(가짜 증서는 실제 계정 로그인과 맞지 않음), 도장 비밀 열쇠 따로 보관 |
| 당첨자가 확인 링크·별을 남에게 넘겨 남이 커피를 받기 | 받아들임(사용자: 당첨자가 주겠다는 것이니 상관없다) | 당첨자 허락 없이 남이 받을 수 있는 길(링크를 가로채기, 별 세 개 없이 초록불 등)이 있는지 찾아 막기 |
| 결과를 본 뒤 회차를 무효로 지우기 | 고침(O10, 11-20) | 운영 서버 배포 뒤 early-seals 확인 |
| drand를 보고 당첨 응모권 끼워 넣기 | 막힘(봉인 시각 증거) | — |
| 화면 코드를 바꿔 남의 서명 받기 | 재현 빌드·화면 코드 해시(11-8) | — |

남은 일을 마친 뒤, 맥락을 모르는 별도 검토자(서브에이전트)에게 "본인 허락 없이 커피를 가져가는 방법"(남의 복구 코드·소속 증서·당첨 확인을 허락 없이 얻기, 운영자 부정 포함)을 처음부터 다시 찾게 해 새 길이 없으면 이 절이 초록이다.

## 4. 준비 완료 신호

다음이 모두 맞으면 사용자에게 "준비 완료"를 보고하고, 사용자가 공지를 올린다.

1. 2절 표의 모든 칸이 초록(실기기 칸은 사용자나 동료가 확인한 날짜와 기기를 적는다).
2. 3절의 남은 일을 마치고 별도 검토에서 새 길이 없음.
3. 정식 시작 예약이 장부에 실렸고(3회차 예고), 정식 일정표가 매시간이며, 정식 첫 회차가 문제없이 닫힘.
4. CI·사이트 배포·운영 서버 배포가 같은 커밋이고, 운영 장부 검사(검증 페이지·터미널 검사기)가 통과.
5. 감시(gatus)에 별 따기 항목이 모두 정상, 이상 데이터 감시(갑자기 늘어난 응모 등)를 둘지 결정.

## 5. 정할 것(사용자)

- 메신저 앱 안 브라우저 처리: 바깥 브라우저 안내 문구와 방식.
- (정함) 퇴사한 사람은 당첨 확인 때 운영자가 직원인지 확인. 동료가 건네준 복구 코드·계정 여러 개·당첨자가 허락한 양보는 받아들이기로 함(2026-10-31).
- 정식 시작 시각.
- 공지 문구(이 문서 1절의 약속과 맞추기).
