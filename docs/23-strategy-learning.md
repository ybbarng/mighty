# 23. 수 배우기: 정석·초반·전술 (2026-10-29 계획)

규칙을 익히는 "배우기"(튜토리얼) 다음 단계다. 장기·체스·바둑은 초반 정석과 자주 나오는 수가 정리돼 있으니, 그것을 직접 두며 익히게 한다.
2026-10-29 사용자 요청: "전체적인 학습이 가능하게 해줄 수 있어? 그건 너무 방대한가? 일단 계획으로 세워두고 하나씩 진행해줘"

## 1. 범위: 전부가 아니라 핵심부터

- 전부는 너무 많다(바둑 정석만 수천 갈래, 체스 오프닝 책 한 권이 수백 쪽). 그래서 게임마다 **입문~초급이 꼭 알아야 할 핵심**만 먼저 만든다.
- 처음 목표는 게임마다 문제·수순 30~60개다. 쓰는 사람이 늘면 그때 넓힌다.
- 수순과 정석 이름은 사실이라 그대로 써도 된다. 설명 글은 책이나 사이트에서 옮기지 않고 직접 쓴다.

## 2. 공통 틀: "수 배우기" 모듈

모든 판 게임이 같이 쓴다. 튜토리얼 틀(단원 → 설명·퀴즈·미션)을 넓혀서 만든다.

- **문제(puzzle)**: 장면 + 둘 편 + 정답 수(여럿이면 모두) + 해설.
  - 예: "한 수 외통", "차를 공짜로 얻는 수"
- **수순 따라 두기(line)**: 정석·오프닝을 처음부터 한 수씩 둔다.
  - 상대 수는 저절로 둔다.
  - 내 수가 다르면 "이 정석에서는 ○○"라고 알려 주고 다시 두게 한다.
  - 갈래가 있는 정석은 나무 모양으로 둔다.
- **진행 기록**: 문제마다 맞힌 날을 남긴다. 틀린 문제와 오래된 문제를 다시 낸다(간단한 간격 반복).
- **검증**: 모든 문제·수순을 단위 시험에서 엔진으로 다시 둔다.
  - 수가 규칙에 맞는지 본다.
  - "외통"이라고 한 문제는 정말 외통인지, 정답 말고는 외통이 없는지 확인한다.
  - 틀린 데이터가 들어가지 못한다.
- 화면: 각 게임 첫 화면의 "배우기" 안에 "규칙 배우기 / 수 배우기"를 둔다(GameHome 메뉴는 그대로 넷).

## 3. 게임별 내용

### 장기(지금 있는 게임, 먼저 한다)

1. **외통 문제**: 한 수(10) → 두 수(10) → 세 수(5)
2. **기본 전술**(10): 양수겸장, 포 길 열기·막기, 마·상 멱 이용, 차 교환, 궁성 대각선 공격
3. **초반 원칙과 포진**: 상차림 넷의 장단점, 초반에 차 길 열기, 졸 쓰임, 자주 두는 첫 수 몇 갈래(수순 따라 두기)
4. **기물 교환 감각**: 점수(차 13·포 7·마 5·상 3·사 3·졸 2)로 이득인 교환 고르기 문제

### 체스(게임을 만든 뒤)

1. **오프닝 원칙**: 가운데, 기물 전개, 캐슬링, 같은 기물 두 번 움직이지 않기
2. **대표 오프닝 10개 안팎**(수순 따라 두기)
   - 이탈리안, 루이 로페스, 시실리안, 프렌치, 카로칸, 퀸스 갬빗, 런던 시스템 등
   - 처음 4~8수와 노림만 다룬다
3. **전술**: 포크, 핀, 스큐어, 디스커버드 어택(문제)
4. **메이트**: 한 수·두 수 메이트, 백랭크
5. **기본 엔드게임**: 퀸·룩으로 메이트, 킹과 폰(오퍼지션)

### 바둑(게임을 만든 뒤, 9×9부터)

1. **기초**: 단수, 축, 장문, 환격, 패
2. **사활**: 살기·죽이기 기본형(직사궁·곡사궁, 매화육궁 같은 이름 있는 모양)
3. **포석 원칙**: 귀 → 변 → 가운데, 날일자·한칸뛰기
4. **기본 정석**: 화점·소목에서 가장 흔한 몇 갈래(수순 따라 두기)
5. **끝내기 기초**: 큰 곳 고르기

6. 바둑: 게임을 만들 때 기초와 사활부터 함께 넣는다

## 5. 설계 다섯 질문(문제·수순 데이터 형식)

1. **데이터의 뜻·연결·책임**
   - 문제
     - `{ id, game, title, scene, toMove, answers: 수[][], explain, tags, level }`
     - `answers`는 정답 수순들이다. 두 수 이상이면 상대 응수까지 넣는다
   - 수순
     - `{ id, name, moves: 마디[] }`
     - 마디는 `{ move, note?, branches? }`
   - 진행 기록
     - 문제 id별로 맞힌 날, 틀린 횟수
     - 이 브라우저에만 남긴다
2. **꼭 지킬 규칙을 어떻게 보장하나**
   - 단위 시험이 모든 문제를 엔진으로 다시 둔다.
   - 외통 문제는 정답 뒤 외통인지 확인한다. 다른 수로는 같은 수 안에 외통이 되지 않는지 확인한다(정답이 하나여야 헷갈리지 않는다).
3. **사람과 AI가 데이터를 어떻게 찾아 쓰나**
   - 게임별 파일(`<게임>/lessons/puzzles.ts`, `openings.ts`)에 자리 이름으로 쓴다(장기 "95", 체스 "e4", 바둑 "D4").
   - 사람이 읽고 고칠 수 있게 한다.
4. **요구사항이 바뀌면 어디까지 고치나**
   - 문제를 더하는 것은 데이터 파일 한 줄이다.
   - 형식이 바뀌면 공통 모듈과 검증 시험만 고친다.
5. **다른 대안과 고른 근거**
   - 외부 문제 모음(PGN·SGF 파일)을 그대로 쓰는 방법을 견줬다.
     - 저작권이 모음마다 달라 확인이 필요하다.
     - 한국 장기는 공개된 형식이 없다.
   - 그래서 형식은 직접 정하고 내용은 직접 만든다. 체스·바둑은 나중에 공개(퍼블릭 도메인) 모음을 들여올 수 있게 가져오기 함수를 따로 둔다.
